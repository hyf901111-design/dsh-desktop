# Task 2 implemented client contract

Bridge: `window.dshDesktop.researchBoards.{isSharedSession(sessionId),getSnapshot(),invoke(action,input),subscribe(listener)}`. `isSharedSession` is synchronous historical-binding classification, including logged-out/revoked bindings; use it before registry/storage initialization to disable/purge shared localStorage mirrors. Subscription returns disposer; page owns runtime/registry/slots and passes only cloneable data. `getSnapshot()` directly returns State. `invoke` always resolves `{ok:true,value}` or `{ok:false,error:{code,message,retryable,details?}}`; no credentials/lease tokens.

## Actions

All inputs are exact objects. IDs are bounded nonempty safe identifiers. Account generation comes from main and cannot be supplied by page. Main generates/persists wire operation IDs. `clientMutationId` is page UUID for local dedupe.

- `favorite.add {identity:{sessionId,title,cwd?,workspaceId?,workspaceTitle?}}` -> Favorite (duplicate session returns existing).
- `favorite.rename {favoriteId,title}`, `favorite.remove {favoriteId}`, `favorite.reorder {favoriteIds}` -> ordered Favorite[]. No login required.
- `board.pin {boardId}`, `board.unpin {boardId}` -> State. Local per-account preference; unpin never leaves/cancels; refresh preserves it.
- `board.create {favoriteId,title?,captureId?}` -> `{board}`. Source must be favorited in main. Calls complete Task4 capture hook; missing hook returns CAPTURE_UNAVAILABLE. Caller then opens board normally.
- `board.previewCapture {favoriteId}` -> `{captureId,sourceRevision,nodeCount,historyCount,assetBytes}` through Task4 preview hook. Missing hook: CAPTURE_UNAVAILABLE. Pass returned captureId to create to consume reviewed frozen data.
- `board.copyPersonal {boardId}` -> `{copyId,title}` through Task4 prepare hook; page then creates a fresh local session; `board.finalizePersonalCopy {copyId,localSessionId}` finalizes through Task4 hook and returns `{localSessionId}`. Main rejects shared, favorited or nonempty destination sessions; Task4 validates the opaque copy handle/account/generation and writes captured portable content. Missing hook: CAPTURE_UNAVAILABLE.
- `request.submit {boardId,text,clientMutationId,targetId?,targetCollection?,source?}` invokes Task4 submitRequest hook before any message is sent, returns hook result; missing hook: EXECUTION_UNAVAILABLE and preserve composer draft. targetCollection files/artifacts, source manual/refresh. Task4 owns stable message+task orchestration, lease/context and result schema.
- `board.open {boardId}` -> `{localSessionId}` if bound, else `{reservationId,title}`. Coalesces reservation. Page creates a fresh session with `sessions.create`, then calls bind. Does not reuse source session. Opening explicitly pins again.
- `board.bind {boardId,reservationId,localSessionId}` -> `{binding,view}`. Reject original/nonempty/another shared session and stale reservation.
- `board.activate {localSessionId:string|null}` -> BoardView|null. Updates current-board event/presence subscription. Call null when leaving Research/shared session. Every call supersedes earlier activation, including null; within the same account lifetime, a superseded asynchronous call resolves null on either success or failure and cannot replace the later selection or presence subscription. Account lifetime changes still return SESSION_CHANGED; the latest activation retains its actual load/authorization error.
- `boards.refresh {}` -> State.
- `canvas.apply {boardId,localSessionId,baseRevision,clientMutationId,canvas:{files,artifacts}}` -> CanvasReply.
- `canvas.undo {boardId,localSessionId}`, `canvas.redo {boardId,localSessionId}` -> CanvasReply. Never call legacy workspace undo in shared mode. Undo deleting a node returns DELETION_RECOVERY_REQUIRED with a recoveryId; `recovery.restoreDeletion {boardId,recoveryId}` explicitly restores fresh IDs while authorized.
- `board.rename {boardId,title}`, `board.archive|restore|cancel|reopen|leave {boardId}`, `board.refreshPause {boardId,paused}` -> durable command reply.
- `user.lookup {publicId}` -> `{user}` (exact 10 digits, leading zeros retained).
- `invitation.send {boardId,publicId,role}`, `invitation.revoke {boardId,invitationId}`, `member.role {boardId,userId,role}`, `member.remove {boardId,userId}` -> durable command reply. role editor/viewer only.
- `invitation.respond {invitationId,version,decision:'accept'|'decline'}` -> server invitation result; acceptance refreshes and pins board.
- `message.send {boardId,text,clientMutationId}` -> `{operationId,pending}` (durably queued, later accepted messages arrive in BoardView). Never call Session.prompt or start AI.
- `notifications.read {notificationIds?:string[]}` -> NotificationView, no invitation response.
- `presence.update {boardId,cursor?:{x,y}|null,selectedIds?:string[]}` -> `{ok:true}`. Null clears the cursor. selectedIds is a transient presence hint limited to 100 IDs; the canvas node cap remains 1000.
- `recovery.saveDraft {boardId,text,clientMutationId}` -> `{recoveryId}` persists only own composer text, using clientMutationId as stable recovery ID; empty text deletes that draft. Call while authorized before access-loss UI clearing; after logout/revocation it is rejected.
- `recovery.get {recoveryId}` -> Recovery; `recovery.dismiss {recoveryId}` -> `{ok:true}`.

## State and events

State `{version:1,eventSeq,account:{status:'signedOut'|'loading'|'ready'|'unavailable',generation,user:null|{userId,publicId,username}},favorites,boards,current,notifications,recoveries}`. Favorite `{favoriteId,sessionId,title,cwd?,workspaceId?,workspaceTitle?,createdAt}`. BoardSummary includes server Board plus `pinned:boolean`, optional localSessionId and optional `sourceFavoriteId`. This source association is account-local and maps an original favorite to already-created shared copies; it is never sent on the wire. Unfavorite/re-add keeps the source-session protection and resolves to the current favorite ID. NotificationView `{notifications,cursor,unreadCount,pendingCount}`. Recovery summaries contain recoveryId,boardId,createdAt,reason,operationId?,status.

BoardView `{boardId,localSessionId,board,connection:'loading'|'online'|'offline'|'revalidating'|'revoked',permissions:{read,edit,manage,execute},canvas,canvasRevision,seq,epoch,history,messages,tasks,members,presence,pendingCount,canUndo,canRedo,recoveries}`. Server record fields remain structured; tasks have lease secrets removed.

CanvasReply `{canvas,canvasRevision,localBranchRevision,seq,pendingCount,canUndo,canRedo,clientMutationId?}`. `canvasRevision` is merged main state. `localBranchRevision` is the exact local fork AFTER submitted edit and BEFORE incoming remote changes. While an IPC edit is in flight, queue local typing + remote hydration. Send next still-local canvas against localBranchRevision, never merged canvasRevision. Once queue drains apply latest merged view atomically. Remote hydration changes files/artifacts once, preserves viewport, sanitizes selection, clears legacy undo and suppresses outbound echo. Unknown base => STALE_CANVAS_REVISION; preserve own draft, do not retry against unrelated newer base. Main retains 128 recent issued revisions and 256 in-memory mutation replies. A persisted duplicate canvas mutation whose old reply was evicted returns MUTATION_ALREADY_APPLIED with operationId/current canvasRevision; do not resubmit with a new mutation ID. Discussion duplicates use persistent clientMutationId -> operationId even after ACK. `pending:false` means already acknowledged, not a new send.

Events are `{type:'state',eventSeq,accountGeneration,state}`, `{type:'board',eventSeq,accountGeneration,boardId,localSessionId,view,cause}`, `{type:'presence',eventSeq,accountGeneration,boardId,localSessionId,presence}`, `{type:'access',eventSeq,accountGeneration,boardId,localSessionId,reason,epoch,recoveries}`. Subscribe before snapshot; discard older eventSeq/generation. Board/presence only current active binding. Access event empties canvas AND shared discussion; never retain full revoked board as personal copy.

Shared legacy canvas sync writes are rejected: use canvas.apply. Main read denies historical shared bindings with `[]`/`{}` rather than null to prevent stale localStorage fallback. Page must disable/remove shared localStorage mirrors; materialized shared remote hydration must not call legacy sync persist. Original private research behavior unchanged. Access revalidation aborts the prior board authority lifetime and stays fail-closed through network errors; only a new successful authorized snapshot restores reads/edits. BOARD_ACCESS_CHANGED means an obsolete per-board HTTP/event/ACK response was discarded, including responses from before revocation. A later independently initiated open or refresh may reauthorize the board.

## Task4 main hooks

Actual `ResearchBoardHooks` is exported from `src/main/research-boards-service.ts`:

- `captureOriginal({sessionId,accountId,accountGeneration,operationId,captureId?,signal}) -> {sourceRevision,capturedAt,snapshot,assets?,dispose?}`. Complete durable human transcript required. Service persists account/favorite create operation and frozen wire manifest before upload; reuse operationId. Existing manifest sourceRevision mismatch rejects SOURCE_CHANGED. Asset open functions are main-only; Task4 must retain immutable cached bytes across interrupted upload retries. Optional dispose runs in finally after submission/failure; its lifetime must not delete the durable resume cache prematurely. If an asset-backed create committed but its response was lost, retry first probes upload.create with the persisted upload operation. An already activated response supplies boardId; service resubmits the same frozen board.create body without recapturing the original or staging into the closed upload.
- `previewCapture({sessionId,favoriteId,accountId,accountGeneration,signal}) -> {captureId,sourceRevision,nodeCount,historyCount,assetBytes}`. Task4 pins opaque reviewed capture.
- `CapturedAsset {assetId,name,contentType,size,open():Promise<BodyInit>}`. Service uses documented staged streaming routes and caller-generated cloud UUID; no path crosses IPC/wire. Missing referenced asset rejects RESOURCE_UNAVAILABLE.
- `projectLocalCanvas({accountId,accountGeneration,boardId,epoch,localSessionId,canvas,signal}) -> Canvas|Promise<Canvas>`. Task4 strips private materialization fields, maps local assets to cloud UUIDs and uploads newly imported files. Service rechecks identity/permission/board instance after await before committing its exact-base CRDT delta.
- `materializeBoard({accountId,boardId,epoch,localSessionId,canvas,signal}) -> Promise<Canvas>`. Task4 authorizes cached cloud files; service rejects asset-bearing materialization with missing hook, and ignores a stale returned revision/generation.
- `revokeBoard({accountId,boardId,localSessionId?}) -> void|Promise<void>`. Main currently wires preview `revokeSession` and context `invalidateSession`; Task4 extends cache/task cancellation.
- `preparePersonalCopy({accountId,boardId,snapshot,signal}) -> {copyId,title}` and `finalizePersonalCopy({accountId,copyId,localSessionId,signal}) -> {localSessionId}`. These are reserved hooks, not implemented file-copy logic.
- `submitRequest({accountId,boardId,text,clientMutationId,targetId?,targetCollection?,source?,signal}) -> Promise<unknown>`. Reserved Task4 orchestrator. Missing hook never falls back to message-only or Session.prompt. Task4 must preserve mutation identity through uncertain message/task outcomes and publish the exact result type before wiring UI.

Task4 can call main-only `service.command(boardId,action,body)` for typed task commands and `client.request(endpoint)` for fixed asset endpoints; leases are not returned through generic page actions. `service.getBinding(sessionId)` returns the same-account candidate shared binding; `readSharedCanvas`, `command` and canvas.apply enforce live permission. Do not treat the binding record alone as authorization. `service.readSharedCanvas(sessionId)` gives guarded canonical read; never export private original paths.

Common errors: INVALID_REQUEST, LOGIN_REQUIRED, SESSION_CHANGED, BOARD_ACCESS_CHANGED, ACCESS_DENIED, READ_ONLY, CAPTURE_UNAVAILABLE, RESOURCE_UNAVAILABLE, NOT_FAVORITED, BINDING_CONFLICT, STALE_CANVAS_REVISION, DELETION_RECOVERY_REQUIRED, MUTATION_ALREADY_APPLIED, SOURCE_CHANGED, EXECUTION_UNAVAILABLE, STORAGE_UNAVAILABLE, NETWORK_ERROR, and exact server error code/details. Retryable errors preserve pending operation ID. Pending status is not server acceptance.
