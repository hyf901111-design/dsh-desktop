# EWork internal memory runtime

Private Cordis plugin. `apply(ctx)` installs `createMemoryRuntime(ctx)` with the actual `agents`, `sessions`, `sessionPersistence`, and `llm` services. The optional `tokenMeter` service prices the actual transient message against the prepared model's context capacity. It registers no user-callable tools.

`EWORK_MEMORY_BRIDGE` is a JSON object containing an authenticated `http://127.0.0.1:<port>/` URL and token. The desktop bridge owns identity, shared-session exclusion, project binding, the unified memory switch, content versions, manual locks, provenance, deletion barriers, usage state, and persisted pending captures. Capture endpoints are POST `/recall`, `/validate`, `/usage`, `/capture`, `/attempt`, `/commit`, `/failure`, and `/pending`; summary endpoints are POST `/summary-input`, `/summary-commit`, and `/summary-failure`. Missing bridge configuration makes `apply` a graceful no-op so unavailable secure storage cannot veto normal app startup.

The rc.7 `agent/request-context` extension runs after `request/header` logging and immediately before the original `preparedCall.stream`. Pre-step selection is revalidated at this final boundary and after usage recording. A stale selection is retrieved again; repeated changes omit memory and record a generic warning. Actual request messages are immutable copies; transient text is never appended to a session event, request header, or compaction surface. The authoritative block includes priority and no-permission framing and is limited to 1,200 UTF-8 bytes including that framing. When the whole block cannot fit, it is omitted and a visible warning is recorded; no fragment is silently truncated. Existing history compaction and overflow retry continue to own the original history.

Completed parent turns first pass `sessions.flush`, then `sessionPersistence.readFrom` confirms the exact durable `turn/end`. Only direct `source.kind=user` text and assembled assistant text enter capture; plugin context, raw chunks, tools, subagents and plugin-only scheduled turns are excluded. Short confirmations may include preceding context for interpretation, but are not saved as uncertain memories. The extractor saves stable preferences, lasting project facts and explicitly requested continuation context. It omits uncertain facts, one-off task requests, current-output parameters and routine progress. Automatic updates keep one current record and an encrypted version history, so old wording does not accumulate in the editable document. Main only stores candidates that meet the active-memory admission rules; it does not create a user review queue. Existing candidate records are removed from the current document after a one-time, account-local Markdown backup, preserving confirmed memories and the global enable state. Leading exact source excerpts and extraction framing together are bounded to 4,000 UTF-8 bytes. Model extraction uses the turn's routed provider/model, an independent `purpose=memory-extraction` request, no tools, and at most five candidates. Reasoning blocks are accepted and discarded; only text is parsed as candidates. Plain JSON or a single complete JSON code fence is accepted, with no extraction of JSON fragments from surrounding commentary. Evidence must remain an exact substring of the named user event. The serial queue makes one extraction call with at most one retry. Errors expose only fixed generic messages. Commit writes are never retried.

Startup recovery consumes only persisted `/pending` captures and reauthorizes each via idempotent `/capture`. It does not scan old sessions. Each model dispatch first reserves a durable attempt via `/attempt`; the bridge preserves the maximum-two budget across restart. An ambiguous reservation is never replayed. Already dispatched conversation requests cannot retract previously sent memory. Unknown adapter capacity falls back to the bridge byte budget; known capacity uses tokenMeter (or conservative byte estimation if absent).

Memory settings display the original saved records and support per-record editing and deletion through the existing revision-checked desktop IPC. Drafts remain private in preload memory across background refresh and settings reopen, and are cleared on account changes. Editing preserves record status and metadata; a stale revision cannot silently overwrite another edit. Secure storage, account separation, Markdown synchronization and conflict copies remain owned by the desktop bridge.

The settings AI preview has been removed. Runtime no longer reserves summary work, dispatches `purpose=memory-summary`, or polls for summary changes. Existing summary bridge endpoints and encrypted caches are retained for compatibility without clearing saved data. Automatic evidence-backed extraction and recall continue independently.

Focused verification: `npx vitest run test/memory-runtime.test.js`. Tests use real Cordis services, a copied and patched installed AgentLoop, a token meter, an authenticated local HTTP bridge, and a real JSONL backend. Canonical dependencies and shared clients are untouched.

Each turn carries the owner epoch, scope epoch and project ID obtained before enqueueing. Capture rejects stale or absent anchors; durable recovery can only renew authorization for pending jobs with the same stored scope. A disabled use switch returns a quiet request without memory.

Local semantic recall now runs in a separate bundled Node process. Pinned multilingual-e5-small INT8 assets are prepared at build time and verified before use; no model downloads occur during chat. SQLite/FTS5/sqlite-vec indices live in memory, and reusable vectors are encrypted with the existing account-scoped secure store. A 2-minute idle timer releases the process. Missing or invalid assets fall back to keyword candidates, never directly to injection.

The bridge exposes up to 30 unverified candidates with an empty legacy `entries`/`block`. The runtime asks the active conversation model for exact source IDs and quotes, validates them, then packs at most 8 complete records within 1,200 UTF-8 bytes. Same-topic text is insufficient evidence for a missing attribute. Selection uses the lowest supported reasoning setting (off, then low), temperature 0, no tools, and an independent hard 8-second deadline. Malformed, unsupported, timed-out or stale selections inject nothing. Cloud conversation models receive the bounded candidate text for this check. Account/scope/revision are revalidated after inference and immediately before the composed request is returned; raw model reasoning and selection text are not persisted.

Reading and automatic saving have independent settings. Temporary session disable and shared-session exclusions apply to both. Semantic retrieval can be disabled separately. Index rebuilding invalidates the encrypted cache and runs on the next relevant query. The existing user-readable `记忆.md` mirror remains plaintext and editable, so encrypted database storage does not imply that all memory representations on disk are encrypted.

Cold index construction is asynchronous: chat recall immediately uses ranked keyword candidates while a generation-bound worker builds the full account index. It checkpoints encrypted vectors every 128 records, so a rebuild can reuse matching revisions. Project/status/expiry filtering still happens before search results cross the bridge. Warm search has a 1.5-second bound; the background indexing deadline is independent of the chat bridge. Final validation carries candidate IDs/revisions and checks their current expiry and scope, and the per-turn selection cache includes the candidate set.
