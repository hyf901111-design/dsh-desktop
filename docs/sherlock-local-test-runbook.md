# EWork Odyssey 本地测试构建手册

## 触发与边界

用户说“本地启动看看”“构建给我测试”“测试一下最新版本”或同义表达时，执行本手册。目标是把当前开发成果构建成正式 EWork Odyssey 身份的本地应用并直接打开，供少量开发用户现场测试。

本流程必须跳过 Apple 公证，并且不得：

- 上传 Cloudflare R2 或修改任何公开更新源；
- 递增版本号、生成公开 DMG/ZIP 或清理线上历史版本；
- 推送源码、推送标签或触发正式发布自动化；
- 删除、重置或迁移用户现有的工作区、会话、模型配置和凭据。

只有用户明确要求“更新上传发布正式版”“发布 EWork Odyssey 正式版”“发布大版本”或对外发布时，才改走 `docs/sherlock-formal-release-runbook.md`。

## 执行步骤

1. 检查当前分支和工作区，保留并避开与本次测试无关的用户改动。
2. 只运行本次修改直接涉及的聚焦测试和类型检查，不运行全功能测试。
3. 构建并启动本地应用：

```bash
./script/build_and_run.sh --verify
```

构建和开发启动会先检查 `package.json` 中所有 `file:` 本地依赖。拉取新增插件后若安装链接缺失，会自动执行 npm ci 按锁文件恢复依赖并应用 postinstall 补丁（不修改锁文件），再次检查通过后才继续；依赖齐全时不重复安装。缺少源码或安装失败会立即停止，最终包检查也会拒绝缺少插件入口的应用。首次克隆仍需先运行 `npm ci`。

该命令会停止本工作区测试产物的旧进程；仅在工作区内置 Node 缺失时自动执行 `npm rebuild node`；以 `com.evanarts.sherlock` 身份构建 `dist-notarized/mac-arm64/EWork Odyssey.app`；显式禁用 Apple 公证；检查应用主程序、内置 Node 和深度签名后启动应用。

退出和启动存活检查均精确匹配本工作区的应用可执行文件路径。其他目录下同名的客户端（例如使用独立配置的 PPT 对比客户端）保持运行，也不能被当成本次应用启动成功的证据。

4. 对最终产物运行完整的本地包检查：

```bash
npm run verify:package:mac -- \
  --app "dist-notarized/mac-arm64/EWork Odyssey.app"
```

5. 读取真实 EWork Odyssey 窗口，确认看到工作区、会话和输入框等完整主界面，不得把进程存在、HTTP 可访问或恢复页当作启动成功。确认原有用户数据仍可见，并让应用保持打开供用户测试。

## 失败处理

- 若工作区 Node 自动恢复失败，停止构建并报告具体路径；不得继续生成已知不完整的包。
- 若最终包缺少内置 Node，启动脚本必须拒绝打开该包。
- 若出现“Harness 暂时无法启动”，读取恢复页技术详情和 Harness 日志定位真实错误；不得删除用户数据来规避问题。
- 本地测试通过只证明当前机器上的构建可测试，不代表已完成 Apple 公证、公开发布或老版本自动升级验证。

## 双客户端页面与协作验收

本地包支持通过 `--sherlock-local-acceptance-origin=http://127.0.0.1:8773` 连接隔离服务；该参数必须同时提供系统临时目录内互不相同的 `--sherlock-user-data-dir` 和 `--sherlock-app-data-dir`。普通启动没有服务替换。验收启动不自动检查公开更新。

在已核验的集成源码运行 `node scripts/start-native-acceptance-services.mjs`，会在系统临时目录创建本地 D1、SQLite Durable Objects、私有附件存储和四个合成测试账户。账户注册/登录及协作均复用生产处理器，服务拒绝外部网络请求。输出仅包含地址、目录和账户名；本地登录信息位于该目录的 `fixture.json`，不会复用主账户令牌。

需要更新验收服务代码并继续原场景时，先停止旧服务，再传入 `--resume=<原验收临时目录>`；恢复时不重建数据库、不重复注册账户。最终 Figma 第 30 组为 11 位成员（3 个头像加 +8），本地服务验收须覆盖第 11 人正常加入、超出限制仍拒绝，以及真实客户端成员列表滚动和搜索。

先按上述流程构建并核验集成包，再用该**同一产物**的两个独立实例分别传入隔离目录和服务参数。通过原生 UI 登录和操作，CDP 只用于读取尺寸、状态和截图。记录画板 ID、主题、成员角色、操作前后结果和实际包提交；本地双客户端通过不代表公网或多机容量验证通过。完成后退出隔离实例并停止本地服务，让用户原主客户端保持打开。
