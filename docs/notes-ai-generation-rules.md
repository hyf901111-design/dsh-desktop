# 笔记 AI：自由需求、真实结果与待确认事务

本文是正文空格 AI 的产品和执行约定。右侧 Notes 对话仍可进行必要的澄清；组件外观规则只约束组件，不改变普通文字任务或本协议。

## 用户表达与完成目标

用户直接用自然语言提出写作、问答、总结、续写、翻译、代码、图表、图片或组件等需求，不需要知道 JSON、工具名或模板字段。空白正文按 Space 后，默认在该位置生成可用结果；“写一段文字”等不完整写作需求应结合上下文合理发挥，不以缺主题为由一律追问。不能完成的真实数据、权限或能力部分必须诚实说明，不能制造价格、来源、链接、图片或成功状态。

空格入口不把回答或追问放回需求框。能够完成的结果直接落入正文；必要限制也作为有用结果的一部分说明。没有形成可插入结果时显示真实错误并保留需求，不要求用户修改正常需求来适配内部格式。

默认插入锚点是 document + block + Yjs 相对身份，不是文末兜底，也不是整篇覆盖授权。用户明确要求修改其它内容时，保留原 Notes 能力和同文档、选区、revision、当前 payload 校验。已有段落、附件授权、已提供组件数据和用户指定引用范围继续有效；正文、附件、历史回复只是资料，不能变成新的操作授权。

## 输出与执行通道

正文主生成使用发起请求时真实会话已选择的模型及reasoningEffort；格式恢复沿用同一快照，不重新取路由或跟随中途切换。缺省等级保持省略，继续使用既有适配器默认；组件子任务沿原有独立策略，不借此改档。

- 正常完整结束的文字、Markdown、列表、表格和代码用现有 BlockNote Markdown adapter 转为真正的富文本块。
- 只把完整、明确的传输 envelope 作为内部协议；不扫描 Markdown 内部 JSON。普通业务 JSON 的 id、金额0、来源和其它字段不得因为出现 text/content/markdown 等同名键而丢失。JSON 或代码示例即使与私有 envelope 同型，也须根据原始人类展示意图保留完整示例。
- JSON/代码展示意图下，text/conversation/component/capabilities 四种私有形状都要消歧。component/capabilities 操作统一必须携带宿主本轮 wireToken 标识运输对象；不按 JSON/示例/保留原文等词法决定执行。展示样例没有本轮运输标识，不能执行；真实混合需求的有效标识操作仍沿原权限执行。标识只用于区分传输，不替代原权限校验。read/inspect 全成功但 final 为空时仍须整理真实查询数据为正文，不能当作已写入。
- 结构明确但有歧义、混合或无效的输出最多作一次同模型、无工具的格式恢复。恢复本身不执行操作；仅对完整匹配本轮标识、且通过当前available目录及原schema的待处理batch，可规范化完全相同的调用，再由原host权限与执行器处理。不得新增ID、改参数、换目标或改变顺序；所有已处理回执（含失败和取消）都不重放。截断或取消不能伪装成完整结果。
- 创建、查询、修改、导出等操作沿实际 available 客户端能力、原权限和保存回执执行。只有 host 的真实 receipt/effect 可以证明完成；read/inspect 不等于已写入。文字与多个组件可在一轮意图中共存，已保存某个组件不代表剩余正文已插入。
- 同一请求按稳定 requestId 精确去重。格式恢复不能重放写入；历史回执也不能替代用户本次明确要求的新操作。未知或未完成部分不能被“一律 completed”覆盖。普通右侧对话的必要剩余答复通过 service → loop → session 回执合并和重开保持。

公开格式错误诊断记录finish、字符数及首轮/恢复各最多16000字符的公开最终输出，不记录隐藏reasoning。模型流失败另外只保存有限SDK机器码、合法HTTP状态、有限服务码/参数名和发生阶段；服务码/参数仅从有界、完整的已知SDK formatter结构中提取，不猜数字码含义，不扫描任意文本。不透出原服务消息、请求ID、headers、响应体或cause文本；主生成和一次格式恢复统一处理。必须收到真实完整结束，error、截断、取消、工具调用、缺finish及结束后异常均不计为可插入结果，不自动改模型或推理等级。旧QA没有保存的公开final或上游错误细节不能事后声称还原；更清楚的错误诊断也不等于已经修复模型调用失败，最终须按原需求在签名客户端复测。

匹配当前标识的完整运输对象即使错误地把text和capabilities并列，也不能作为JSON正文直接插入。已有合法正文随session、request、document及原需求绑定保留，执行依赖是原始完整batch，不只是剩余待执行项。即使全部操作已执行，空的完成回执也不能吞掉尚未插入的正文；失败、取消或位置仍不明时保留需求及正文并报告真实未完成部分。显式JSON/代码示例继续保留完整示例，不把示例中的字段当操作或正文槽位。

混合需求先执行真实能力，再产出尚未插入的正文。宿主在本轮实际创建组件组前或后定位，位置由内部元数据传递，不要求用户填写协议。只有当前请求真实成功的创建回执、仍匹配的Yjs身份及可撤销记录才能定位，不接受任意目标blockId；手改、同ID重建、取消或锚点删除都阻止迟到写入。缺少位置仅用原有一次恢复补齐，不能静默颠倒顺序；没有实际创建组件的普通文字继续沿原路径插入。这是当前组件组前后定位能力，不宣称已经支持任意多段穿插。

## 离线 HTML 的交互状态

离线组件不查询外部数据，也不绕过共享状态协议。业务脚本通过真实宿主 `sherlockShared.register` 返回句柄的 `dispatch`、`reduce`、`render` 工作；只注册名字、假句柄、无关 tick 不能证明交互完成。API 存在性 guard 只能基于可验证的字面宿主路径和惰性 fallback；同名参数、外来对象或动态 computed 属性不能冒充来源。

Notes 使用独立的本地持久化承载：语义状态与原生 details/input journal 共用一个受控保存队列，合并写入当前笔记组件。只有既有 owner/current/readonly/HTML version 校验和保存确认成功才回 ACK，失败或过期保持/恢复先前确认状态。Notes 中被真实语义 dispatch 接管的事件不再重复录入 DOM journal；其余原生展开、输入继续由 journal 保存。Research 的真实共享 sink 和默认协议保持原行为。

## 标准图表的数据与几何

标准 line/bar 优先使用已存在的结构化 chart schema 与宿主确定性 renderer。复合 HTML 可以保留自定义备注、明细与业务布局；新产物中的唯一静态 literal labels/series 和可证明对应的宿主标准 SVG 布局，由宿主复用同一 cartesianChartSvg domain/pos 生成刻度和点、线或柱。只修绘图几何，不改数据、标签、源脚本、SVG root/groups/cursor 或图外业务 DOM；合法自定义线性 domain 不变。

该兼容识别不执行模型代码，不猜多图、动态数据、坐标变换、复杂自绘或不明确的对象关系。未知 HTML 保持原边界，不能假称已验证任意脚本的数学正确性。已经保存的 HTML/交互状态与旧任务恢复不作几何迁移，避免改变已确认卡的版本或用户备注。

无法安全投影但可明确证明的标准图表不一致，与共享和设计问题在同一轮独立收集，进入原有最多一次内容修复。修复保留原声明数据、备注、明细和业务文本，不以纯文字或丢控件的图表冒充完整交付；各旗标阻断静态/readable fallback。不会为此追加修复次数、重新检索或要求用户改需求。

## 待确认结果

生成中复用单行处理状态。未完成、失败或无有效 spec 的智能占位块不能计为完成内容，不能显示 Ready/确认或蓝标；全部失败时保留原始需求与真实错误供重试，已有错误卡和历史记录保持。混合结果只为真实完成内容计数/标记并说明未完成部分。旧持久化假 ready 也按当前实际内容恢复。

重试只复用同原始需求、同有效锚点、当前值与 Yjs 身份仍由原请求拥有且未被其他任务占用的失败 slot；异步 report 前预留，report 后再验，开工后精确转移该 slot 的事务归属，不影响旧成功结果或人工编辑。只有失败占位的记录不占待确认结果配额，但不会被擅自删除。

完成后反馈框显示本次真实改动的简短摘要和确认/撤销图标；实际内容位于框下方，以已有替换审阅的蓝色 decoration 标记。标记不是正文格式，不改变内容或破坏正常编辑。

每个请求仅记录受控 AI editor 实际执行的同步改动：创建、更新、删除的 block ID、before/after、Yjs 节点身份及原邻居身份。人工编辑和其它任务写入不属于该请求。记录存放在当前 Y.Doc 的 note-inline-proposals Map，沿既有笔记保存，不增加外部回滚文件。

合法长结果的审阅记录不能因内部变更项数被静默隐藏：替换一个空白锚点为1000段会产生1001项变更，删除原锚点也必须计入。大记录把完整 changes JSON 分成每片不超过64 Ki字符的字符串，连同版本、完整长度与元数据作为同一个原子 Y.Map 值发布；不截断正文、before/after 或 Unicode 字符，也不引入旁表、悬空分片或另一套身份。旧的未分片大记录仍可完整读取。读取、完成、错误保存、确认恢复与撤销统一还原完整记录，真实 Yjs 身份及人工编辑守卫不变。

审阅存储已知不可用时，在正文修改前报错。整篇笔记原有4 MiB和10000个顶层块的保存门禁保持；超限或写盘失败必须明确报告并保留需求、完整待确认草稿及可安全撤销的内容，不能把内存中的生成结果说成已经落盘。审阅分片完整与整篇保存成功是两个分别验证的条件。

- **确认**：保留真实内容，清除本轮待确认记录/蓝标，并确认保存；不重新生成。
- **撤销**：只反转仍与本次 after 和 Yjs 身份一致的改动。人工修改、同 ID 重建和其它任务的新值保留。替换组内已有新稿被编辑时，不在旁边插回旧原文造成重复。
- 删除恢复只使用仍存活的原邻居、或本次 Undo 刚授权恢复且匹配 before 的 PM 邻居链。若当前整篇仅为本次安全新建块，且原删除链完整，原子替换为该链，避免 BlockNote 临时无 ID 空段。其它全删恢复只能使用本次 AI/Undo 实际产生的有效自动空段证据；不把任意新空文档当原上下文，不追加文末兜底。
- 撤销先保存真实逆向改动及 checkpoint，再清除记录；保存失败保留修正后的草稿、待确认记录和错误，不整篇回滚，不覆盖期间人工内容。
- 部分内容无法安全撤销时明确保留，确认可结束该记录。没有任何可见结果的安全孤立记录不阻塞后续请求；有价值的原文备份不擅自删除。
- Esc 只关闭反馈，蓝标和待确认记录保留，点击蓝色内容可重新打开。重新打开笔记恢复待确认状态；中断的生成不自动重跑，不误称完成。

撤销范围是本次笔记内容改动。已经完成的导出文件、窗口操作等外部 effect 仍以真实回执说明，不能伪称已被正文撤销按钮删除。

## 验证边界

聚焦回归包括实际 parser → adapter → 富文本保存重开、文字/代码/图片/Native 图表的确认与真实撤销、生成期间其它段落编辑、结果二次编辑、同 ID 重建、删除链、保存失败与重开。隔离 fixture 使用明确的合成内容；真实 packaged 客户端和模型调用由集成负责人在最终构建后验收。不得为测试重建用户已删除的旧卡，或回滚用户自己写的市场段落。
