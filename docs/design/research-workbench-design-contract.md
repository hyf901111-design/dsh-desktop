# 研究画板组件视觉合同（第一阶段）

> 本页记录第一阶段源模板及其Figma实例尺寸；包括表中的48px标题区，均不是当前所有模式的宿主chrome规则。当前对话、Research及笔记的外框/标题栏/正文与状态规则以[研究看板组件实现合同](../research-component-design-contract.md#当前模式与宿主外观)为准，原稿实测值保留。

源文件为 Figma `Jkyr5rMvgM8GNH6E68xnqd` 的 `21M 工作台组件设计规范`。图片仅用于定位；属性以源节点为准。运行时合同版本为 `21m-20260923-v1`，实现位于 `workbench-design-contract.js`、`market-artifact.js`、`bento-layout.js`。本阶段使用模拟行情验证，不依赖远程市场数据。

## 职责边界

1. 规划器选业务组件类型，给出有口径的结构化数据。K 线必须用 `market.candlestick` 和 OHLC/成交量；不允许折线替身。
2. 宿主按版本化模板控制字体、色板、深浅主题、内部控件、尺寸和布局。模拟数据批量路径直接渲染，因此不依赖子智能体阅读 skill。
3. 内置 `ework-workbench-components` skill 负责选型、数据完整性、证据与交付协议。它不能以自写 CSS 覆盖标准模板。任意 HTML 属于需单独验收的例外。
4. 验收先查数据 schema 与模板匹配，再查真实客户端的 Light/Dark、默认宽高、窄窗与拖放缩放。模型自述与单元测试不能替代可见结果。

## 后续扩展门禁

新增组件族时先在 Figma 记录 Light/Dark 配对节点、视觉参数与数据 schema，再在宿主注册模板、适配尺寸和语义验证。没有对应模板的需求应明确显示缺项或作为 HTML 例外进入单独验收，不能悄悄使用近似组件。每个模板使用同一数据案例对照 Figma、浏览器渲染和打包客户端，并检查真实缩放、裁切和交互。只有完成这些步骤后，才能声称该组件族达到设计稿一致性。
