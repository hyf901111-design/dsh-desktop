## 运行证据

- 浏览器中十一类面板在浅色和深色均有内容，均无横向溢出。默认尺寸下热力、六项运营指标和日历的内容高度分别等于或小于 210、232、268px 可视高度。趋势内容在 536×216 可视区内无溢出；320×172 窄卡内容高和宽均不超过视口，12 个时点的完整数据仍可展开。
- 交互检查：资讯搜索后 `1 / 8` 条、报告展开 `8 / 8` 条、明细按价格升序首值 `38.46`、K 线方向键更新 OHLC、日历点选日期后显示 1 项并可恢复 8 项。
- 320×220 窄卡：指标与明细保留内部滚动；日历切为纵向布局，内容可滚动且无横向溢出。
- 聚焦回归：`npx vitest run test/research-market-artifact.test.js test/research-interactive-artifact.test.js test/workbench-design-contract.test.js test/structured-workbench-generation.test.js test/research-workbench-multi-scenario.test.js`。
- 可复测性能：`node scripts/benchmark-research-workbench-parity.mjs`，100 次十面板批量校验和宿主渲染平均约 3.6ms，输出 372,067 字节。改动前同机基准约 6.44ms、779,672 字节；主要减少了每张金融卡内嵌字体的重复体积。该数字不包含模型规划、客户端画布挂载和网络耗时。
- 已有打包客户端中的旧版三金融组件曾实际生成并显示；那次从发送提示词到交付耗时 3 分 27 秒。该时长主要是模型规划链路，不可用宿主毫秒级基准代替。

## 本次生成、尺寸与画布联动

- 金融模拟数据如果被规划为通用 `dashboard`、`kpi`、`table` 或折线 `chart`，在创建卡片前转为对应的宿主 `market.metrics`、`market.table`、`market.trend`；不具备专属源稿的金融柱图给出明确的类型错误，避免输出一张貌似完成、实际不符设计的卡片。
- 源稿金融尺寸用于首次生成和整理；研究画板整理的宽度上限由 1380px 缩至 1088px，避免四列金融卡在默认视口整体缩小。十卡模拟组的可读首屏视口保持 1 倍，后续卡片留在可平移的画布上，顺序和原尺寸保留。
- 已由用户手动设置尺寸的卡片不参与自动重排；模板在窄尺寸内使用可滚动内容或响应式高度，不以缩小字体、丢弃列或截去数据来满足外框。
- 打包技能 `ework-workbench-components` 更新了优先使用固定宿主模板、一次批量生成、默认尺寸和严格设计门禁的规则。聚焦验证覆盖 79 项相关 Vitest、TypeScript typecheck，以及 18 项真实宿主生成视觉检查；未运行全量套件。

## 打包客户端端到端回归

- 第一轮医药三组件实测耗时 1 分 34 秒。规划器两次省略 `market.variant` 被拒后修正；金融内容虽已使用宿主模板，完成时外框被通用尺寸回退为 656×220 和 656×456，第三张卡停在等待态，**本轮不通过**。服务端任务记录显示三项已完成，问题在画布接收与通用扩容路径。
- 修复后第二轮黄金三组件实测耗时 46 秒、首 token 2.2 秒。三张卡在同一次计划交付时均已完成，真实画板与计划记录一致：核心指标 896×144、趋势 536×264、明细 536×258；八行明细及三条归一化同轴趋势可见，没有等待卡和大块空白。省略 variant 可按明确的数据形状补齐，避免重复调用工具。
- 第二轮画板为同时容纳三张卡仍缩到约 0.76 倍，因此本轮继续把金融组的默认可读阈值提到 0.85：优先展示前两张，第三张保留在可平移画布上。该调整已有源码回归，仍需在重新打包的真实客户端确认首屏缩放和整理交互。
- 第三轮银行三组件在重新打包客户端 33 秒内全部完成，源稿尺寸保持；真实画板暴露出即时完成的批次绕过终态整理，表格位于视口右侧且上方留白较多。已在批次挂载时按当前画布宽度重新排版；896px 窄画布的三张金融卡在宿主回归中按原尺寸单列落位，待下一包实测。
- 用户指出画板放大后的表格文字像素化。实际表格是嵌套网页中的文字；在“放大阅读”里边缘清楚，画板变换放大时仅网页内文字发糊，外层标题仍清楚。对已验证的金融明细模板改由客户端原生 DOM 绘制表格文字，保留排序、色义和行列样式；其他不受信任的 HTML 继续在隔离网页中显示。该修复已过 81 项聚焦回归，仍需打包后视觉复核。
- 第四轮客户端复测中，原有银行表格已直接成为画板 DOM 文字，AX 中不再出现明细 `about:srcdoc`；按最新价升序后首行为 4.52，排序行为保留。新建三卡在 38 秒完成并纵向排列，但首次视口仍停在原中心，造成明显顶部留白和最后一张卡低于首屏。已把批次挂载时的视口计算与排版原子提交，并让后续聚焦使用相同可视高度；源码回归要求三卡上下左右均在画布边距内。
- 第五轮重建客户端以银行六指标、三序列趋势和八行七列表格复测，44 秒完成。首屏三张卡在可视范围内纵向排列，没有顶部大留白或等待态；明细仍为原生文字，价格升序后首行为中国银行 4.52。放大阅读中的表格虽然清晰，却仍沿用画布 11px 字号，因此补充阅读态 14px 正文、12px 表头和更宽的单元格间距，待再次打包复测。

- 按用户的阅读目标，宿主尺寸规则进一步由内容决定：六项以内指标沿用 896×144，七至十二项为 896×232；金融表格六列及以上改为至少 656×320，超过八行每行增加 24px、总高封顶 456px 后内部滚动。大表正文提高到 12px/18px，放大阅读提高到 14px/21px；默认布局、拖拽下限和内层滚动共用同一密度口径。此项是为可读性做的明确设计修正，不能再把大表标为与 536×258 源稿像素一致。

## 结论与仍需完成的门禁

目前不能宣称“以后所有类型都严格符合 Figma”。金融指标、趋势和明细有可对照的源节点，趋势已补齐源稿主要结构；日历的结构偏差已修正；资讯、报告、运营指标和三种特殊市场图仍缺类型专属的浅深源稿或同数据视觉对照。下一轮应为这些类型指定源节点，建立每个类型的同数据双主题截图基准，再把未通过的类型阻止标记为“设计达标”。实际客户端的十一类型首轮成功率和模型耗时也需要单独复测，宿主渲染成功不能冒充端到端成功率。
