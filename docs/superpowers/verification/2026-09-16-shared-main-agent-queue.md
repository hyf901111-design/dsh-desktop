# 协作看板主智能体与共享排队

源码基线：sherlock-desktop 本地 main 83e2c87。功能分支：codex/feat/shared-main-agent-queue-20260916。

## 行为

- 右侧根对话使用发送者在该看板绑定的原生主智能体，保留原生工具和子智能体创建/调用能力；组件生成继续走原有子任务与格式修复流程。
- 服务端决定队列顺序和执行租约。前一轮及其组件任务未结束时，下一轮不能获得根会话执行权。
- 开始下一轮时读取最新共同上下文，包括前一轮完成的回答，不把其他排队请求混入当前提示。
- 输入框上方复用普通对话 QueueDock。每行依次为图标、用户名、消息、操作；多人可见，作者可编辑、删除、插队。Cmd/Ctrl+Enter 空草稿时提升自己的排队消息。
- 插队先请求停止当前执行，执行端取消主智能体与后代，等原生 subagent/end 回传完成并重新确认主智能体空闲，再确认释放；不将不同用户的指令塞进同一主智能体轮次。
- 未开始的队列保留在服务端，作者重新打开看板时恢复等待。已执行或结果不确定的任务仍要求显式重试。

## 明确未完成的上线验收

浏览器验证运行的是实际客户端组件和本地协作服务，模型执行使用受控测试执行器；原生主智能体与委派适配通过契约测试验证。尚未用真实模型和两个打包客户端做端到端验收。未替换共享客户端、未部署 Cloudflare、未推送远端。

必须先更新协作 Worker，再让新版客户端启用。新版客户端收到缺少 conversation 权限标记的旧服务响应，会在模型执行前停止。排队作者离线时保留位置，需作者重连或删除；不会由其他账户代用其主智能体。
