# EWork 简化记忆设置后继计划

用户最新决定替代原复杂设置：一个总开关，同时使用及自动保存；可直接打开记忆.md目录；真实AI内容概括预览。文件支持正文编辑与条目删除同步，原会话保留。

基线 cf807071；独立feature memory-simple-20261014，避免旧有效交接门禁被WIP阻塞。

- 主进程实现owner分区的记忆.md：目录0700/文件0600，原子写入、不跟随符号链接；外部有效编辑同步到当前owner，带文档签名防陈旧编辑覆盖，删除清除缓存/历史/队列/使用引用；文件错误保留原文并停止召回。SQLite保留加密元数据缓存，目录实际可读写文件是真实记忆内容。
- 原生trusted IPC打开当前owner目录；设置总开关同时控制use/auto。
- 修复reasoning模型提炼：仅解析text，丢弃reasoning，拒绝tool-call；保持无递归及证据校验。
- 通过同一合法模型生成中文AI概括；只读当前owner records，缓存签名、原子预留、失效验证、关闭不生成；无假概括。
- 重写简单UI，保留普通settings结构及两种主题、异步身份安全；选区保存仍可直接记住。
- 聚焦RED/GREEN、完整新增相关子集/tsc、独立review、中文提交、新卡protected append/merge、统一runbook打包与native实际测试。禁止fullsuite、公证、版本升级、上传、推送。

Review Focus：跨账户文件与概括隔离；陈旧编辑/删除不恢复旧正文；AI概括不进原会话；单总开关与文案一致；真实Markdown目录不是空入口。

独立审查修复：旧双开关状态按关闭迁移，服务统一总开关；概括预留包含scopeEpoch，沿用每签名最多两次的持久预算；文件异常在validate/attempt/commit等最终边界撤销授权；文件与加密缓存以先提交意图、后原子替换、再完成意图的可恢复协议同步，旧编辑器冲突另存同目录私人副本并恢复当前文档；没有可信模型路由时显示等待一次对话，不显示正在生成。多行旧标题通过隐藏元数据无损往返，分组标题去除结构换行。上述5项Important及1项Minor全部修复，无延期项。

取舍：用户要求可直接编辑记忆.md，因此明文用户文档与加密内部状态并存，均按账户分区并限制本地权限；后台概括只沿用已成功对话的可信模型路由，新账号手动记忆会等待一次对话；冲突保留双方内容，自动恢复最新文档，用户可自行对比冲突副本。正常关闭会保留已存记忆与已有概括，停止新读取、提炼和概括调用。
