# 组件生成可靠性修复

目标：让真实数据决定呈现方式，减少已取到数据后因配置或格式失败而重新生成；保留明确图形要求、数据真实性和来源校验。

## 已核实的问题

2026-11-07 用户提供的双页签工作台共 10 卡，持久任务记录最终为 7 完成、3 失败。检查对应子任务的原始记录，而非从失败提示推测：

- 两个原生行情面板附带 `selectedSymbol` 后被配置校验拒绝，退化为逐卡模型生成 K 线；原配置只有一个已确认证券，其他周期及指标均受支持。
- 一份已返回的 Tushare 日线映射使用 `YYYYMMDD`，图表要求 `YYYY-MM-DD`，产生 OHLC 结构错误。
- 财务对比的 `income` 响应含完全相同的重复记录，按报告期选择后 `$single` 因条数大于一而失败。
- 另一张 K 线卡在无工具的恢复阶段长时间构造映射，最终超时。先修正错误路由，避免让模型重建已有专业行情能力；不简单延长超时或放松数据校验。

这些是本批次的证据，不能据此宣称全局失败率或承诺零失败。

## 方案和边界

先理解需求与已有资料，按授权查询真实数据，核对字段/实体/口径/时间/单位，再选用可表达这些信息的视图。模板指导样式和交互，不要求补造业务字段。原生能力能完整承接需求时直接挂载。显式历史快照、模拟、多标的对比与原生不支持资产仍保留各自路径。

确定性兼容只处理不改变含义的情形：行情选择字段合法；单值选择中的整行完全重复；真实交易日期的等价格式。不同记录即使所选值相同仍不合并；列表、求和与样本分布不去重；缺失只在显式 optional 时返回 null；非法日期、OHLC 关系、来源或时间范围冲突继续失败并提供可修正反馈。

## 执行与验证

- [x] 原生行情配置：复现单标的 `selectedSymbol` 的降级，修正合同并验证两张 K 线不启动模型。
- [x] 映射：先添加重复财报、真实冲突、optional 空值、日期格式的失败用例，再实现等价兼容。
- [x] 提交/刷新：相同真实响应通过提交、物化与刷新路径，不重复查询；保留价格、单位、原始记录。
- [x] 规则：更新组件 Skill 与运行时的初始/恢复提示，统一数据先行原则与可操作的映射示例。
- [x] 仅运行直接相关检查，中文本地提交，生成交接卡；不改用户数据，不构建共享客户端，不发布。

## 实际结果与限制

原失败财务映射及四份完整 Tushare 响应只读回放后成功生成两家公司比较表，原始响应未改写。两种K线格式的日期转换、刷新复用及非法日期/OHLC拒绝均有回归覆盖；两张原生K线配置通过准备批次直接完成，不创建模型任务。规则压力验证指出的旧K线强制模板冲突已清理。未调用线上模型重做整板，也未修改既有用户工作台。

原有额外布局测试存在依赖补丁锚点漂移：research-grid-additions 的 conversation-response-progress anchor；workbench-semantic-layout 的 Workbench publish anchor。已通过实际序列化客户端双页签浏览器检查覆盖本次布局修改，不以这两个历史测试的失败作为本次通过。
