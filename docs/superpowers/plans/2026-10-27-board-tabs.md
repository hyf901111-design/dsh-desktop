# 看板页签组件实施计划

**目标：**按 Figma 最新 V3–V9 契约实现组件库页签、设置和跨页拖入，并自行进行聚焦使用测试。
**架构：**页签为 generated-container 的 board-tabs 原生组件；页签及组件归属保存在同一 containerSpec 中，使用现有看板提交、协作与撤销。每页复用独立网格状态，活动页与视口为本地视图。原组件 ID、内容和连接保留。
**技术：**现有 React 序列化客户端、原生 CSS、Electron、Vitest。
**设计依据：**dsh/output/figma-session-tabs-v3-20261027/interaction-contract.md，后续 V5、V6、V7、V8、V9 修订及在线节点 3201:365392、3245:393516、3351:365347。

## 约束与核对重点

- 导航满宽、高34px、页签64×26、12/18文字居中；不允许缩放，空页不增加提示。
- 设置480px、24px内边距、16px圆角、38px输入框；列表最大328px，仅列表滚动。
- 首放建立两页，重复添加定位已有导航；取消拖入不产生任何变化。
- 删除含内容页需确认；草稿撤销/取消保留原数据；保存按版本校验且一次事务。
- 跨页移动不复制、不缩小实际尺寸；拖影64px接近缩略、96px退出、160ms；Escape或无效释放取消。
- 只运行相关测试和类型检查，不运行全功能单元测试、不发布。

## 快速图表拖放的最终预览策略

- 原生回归发现快速手势中截图可能迟于松手，导致短暂文字占位。最终改为在近区直接变换同一个真实组件DOM；不复制、不重挂载iframe，不依赖截图到达时间。
- individual translate只负责指针跟随，transform同时插值抓取偏移及缩放。离开近区还原原生浮动坐标；释放在原元素上执行连续变换。原生落位槽在近区淡显。
- 缩略限制在画布可见范围内，同时受宽度240px和可用高度约束；覆盖原生拖动定位样式并遵循减少动态效果偏好。
- 实际客户端已验证普通移动/撤销、重复添加及2秒后消失、九页在窄宽下翻页和边界禁用、恢复宽度后隐藏。新增独立验证看板“页签交互验证 · 10月28日”，未改动原测试看板的日历和两页配置。
- 最终130项相关检查、类型检查、补丁可重复应用/还原均通过；本次直接DOM方案待最终构建后核验图表不闪烁。
