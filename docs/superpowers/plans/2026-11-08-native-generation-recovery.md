## 方案与边界

1. 从声明的 table 单元格上下文编译单值选择，复用已有 `$single`：保留筛选、排序、单位换算、原始字段和缺失声明。整行完全重复可等价， distinct records 继续报歧义；不任取、合计或丢弃字段。归一化后的配方须支持后续刷新。
2. 错误指向实际 row/cell/字段，避免误导模型重写 columns。
3. 自动恢复采用不同策略：宿主无损归一化 → 一次基于已取得资料的定向修复 → 仅对呈现失败切换宿主来源明细快照。保留全部真实记录、字段、单位、来源和时间，说明对比/交互/自动刷新未完成；不以错误说明充当内容，不把缺失当零。明确指定的 K 线、交互、来源要求不擅自绕过。
4. 对取数失败保留已成功响应，重试/备用来源必须受原授权范围约束；禁止无限重试、无意义重复请求或通过降级绕过取消、来源、单位、日期和权限检查。
5. 最新 UI 跟进：选中壁纸 hover 上浮 2px 被分页 overflow 裁切，clip-margin 6px 修复，宽窄浏览器检查通过（`81fe70396`）。右侧锚点 gap 8→2px、圆点 4→5px，保留 24px 点击区（`25b9894a8`）。仍需集成到 main 后重构建及原生验收。
6. 来源明细备用交付使用持久 `deliveryStatus:partial/recoveryMode:source-snapshot`，保留未完成项。画布汇总单列来源明细，不计完整成功；允许重新生成并保留旧资料。完整元数据包括结构化单位/币种/数据时点/来源 partial/缺失范围。任何原需求图形、显式交互、刷新或指定来源约束都阻止静态替代；多卡原需求不能可靠划定图形范围时保守阻断，不依据模型规划擅改。
