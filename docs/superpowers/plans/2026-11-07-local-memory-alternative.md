# 应用内本地记忆替代方案：设计与隔离样机

日期：2026-11-07。状态：替代路线与样机验证，尚未接入产品。

## 用户目标与范围

用户在缺少统一后端测试环境时要求“换个本地存储和应用记忆的方案”。因此停止 Hindsight 后端推进，选择不需要单独服务器的嵌入式方案。沿用“先验证，再改造记忆架构和前端”的顺序；本次先交付可复现的替代方案和隔离样机，不把实验通过等同客户端交付。

用户已要求自行判断、非必要不确认。本方案的库选择与验证门槛是工程判断，不冒称用户指定的技术或 SLA。旧 Hindsight 的资源门槛不沿用。

## 现状核查

- `MemoryStore` 已使用 `node:sqlite`，每个账户保存一份系统安全存储加密的 JSON 状态。
- `MemoryRetriever` 已有内存 FTS5 trigram 与中文二字片段；排序对 preference 等种类固定加分，缺少向量语义召回，无相关结果也可能注入项目背景。
- `MemoryService` 已有来源、版本、过期、候选、删除抑制、身份切换和会话项目绑定。保留并复用这些治理规则。
- `use/auto` 当前被强制联动。后续应拆成“使用已有记忆”和“自动保存新记忆”，并单独控制临时会话。
- SQLite 正文加密不等于全部文件加密：现有实现还自动写出可编辑的明文 `记忆.md`。替代方案需要明确镜像模式，不能宣称已有全链路加密。

## 方案比较

| 方案 | 能力与代价 | 决策 |
| --- | --- | --- |
| SQLite + FTS5 + sqlite-vec + 本地小型 embedding | 直接嵌入 Node/Electron；无需 PostgreSQL 或常驻 HTTP 服务；保留现有治理；需验证本地推理、原生库打包和索引生命周期 | 推荐并验证 |
| Mem0 嵌入库 | 已封装 add/search/update；仍需配置 LLM、embedding、向量与历史存储，当前治理层需要重新对接 | 此轮不采用；不是断言其不能本地运行 |
| 纯 Markdown/现有关键词排序 | 零模型依赖、直观可编辑；不能充分解决同义改写、跨条关联和无关背景注入 | 作为导出与降级能力 |

参考：[sqlite-vec Node 文档](https://alexgarcia.xyz/sqlite-vec/js.html)、[SQLite FTS5](https://www.sqlite.org/fts5.html)、[Mem0 OSS](https://docs.mem0.ai/open-source/overview)、[multilingual-e5-small 模型卡](https://huggingface.co/intfloat/multilingual-e5-small)。

## 建议产品结构

1. 持久层：按账户/记录保存加密正文、版本和 embedding 缓存；内容与索引修订绑定。最初复用现有加密状态库，逐条存储升级须保留旧库备份并验证迁移/回退。明文 FTS/向量搜索索引只驻留内存；既有 Markdown 镜像保留用户选择，不在升级时默默删除。
2. 检索层：先按当前账户、项目、状态、有效期筛选，再结合中文分词全文检索和向量召回；合并候选后按相关性选择完整来源片段。未知问题的最近邻候选不能直接当作事实答案。
3. 应用层：在模型请求前注入有限预算、带来源和版本的记忆；过时状态不作为当前事实。用户当前要求优先。后台提炼只处理符合现有来源规则的已完成对话，自动保存与读取开关独立。
4. 生命周期：本地推理在专用 worker/utility process 中按需启动，空闲释放；关闭记忆或切换账户时取消在途任务并拒绝旧 epoch 的响应。无需外露网络端口。此项需后续真实客户端测量。
5. 联网边界：手动记忆、检索和查看可以离线；自动提炼若沿用云端会话模型，仍会向所选模型发送必要文本。不得以“本地存储”承诺全部 AI 处理离线。此轮样机只测试已保存记忆，无模型 API 调用。

## 前端设置建议

- 使用已保存记忆；自动保存新记忆；当前对话临时禁用。
- 查看、搜索、编辑、删除，按个人/项目、分类、状态筛选；来源、确认时间、被哪次对话使用。
- 待确认与冲突处理；旧版本与当前有效版本分开；进展记忆有效期。
- 本地语义检索开关、模型准备/索引状态、重建索引和占用显示；普通界面不暴露向量维度等工程参数。
- 导入/导出，明文 Markdown 镜像的明确说明与选择，删除记忆后清理其索引与派生摘要；保留原聊天记录这一边界。
- 本地优先不含多设备自动同步。同步将是独立后续功能。

## 隔离样机：执行前冻结

仅使用合成数据和仓库外运行目录；不修改产品源码、真实用户记忆或共享客户端，不安装依赖到产品根目录。

- Node `node:sqlite` + sqlite-vec 0.1.9 + ONNX Runtime Node 1.31.1 + Hugging Face tokenizers 0.2.0。
- 复用已下载的官方 multilingual-e5-small 快照 `614241f622f53c4eeff9890bdc4f31cfecc418b3`；INT8 文件 SHA-256 `dd476dd0c2514e9b9be83aeb3853fac0763e0bdf4a71645407587d77c48a2d88`。模型 query/passage 前缀、masked mean pooling、L2 normalization 按模型卡实现，不经过 Hindsight。
- 固定旧 46 题语料 SHA-256 `73017f842f5ca6cfd4b24d1e91fc73800b6aa2a515333801b2ae85bbf516c961`。
- 沿用尚未执行检索的新 24 题保留集 SHA-256 `7abdbceaa3ef0951aebe35b826bd87daff6b1745374c125fecd8e1ca9d9338fc`。20 正例、4 无答案；不根据结果改题。
- 分别报告纯语义、中文 FTS 与固定融合（RRF k=60，语义权重 0.75、词法 0.25），在查看结果前固定。无答案候选与最终生成幻觉分开。
- 原 40 正例 top-5 ≥90%，原语义改写 ≥12/14；新 20 正例 ≥90%；完整 1,200 UTF-8 字节证据覆盖 ≥95%。这是是否值得继续集成的参考，不是产品最终验收。
- 额外 1,000 条冻结规则生成的合成干扰记忆；1/3/10 个客户端请求并发，各至少 200 次。完整调用计入队列、查询 embedding、SQLite 查询和证据打包；失败和超时不得剔除。单请求热态 p95 ≤500ms，3 并发 p95 ≤1,000ms；10 并发只做桌面容量诊断。
- 账户及项目隔离、同名 ID 更新删除、失效状态与过期过滤、重启后持久性：越界返回 0。只能称样机边界，不能替代真实账户切换与 Electron IPC 验收。
- 记录启动、数据大小、依赖和模型体积、样机进程 RSS；不再自行设置硬性内存门槛。

## 晋级与剩余工作

样机只决定是否继续采用该技术组合。产品集成还需要：原生库签名/双架构打包、worker 取消与账户 epoch、真实迁移恢复、无答案相关性门槛、自动提炼准确性、独立开关与前端真实交互。前端与产品代码不在本样机内假装完成。
