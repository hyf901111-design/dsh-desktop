# 对话检查清单的首屏生成与定向修复

## 问题与目标

真实本地对话连续提交三份交互式研究检查清单，HTML 结构合法，但初始正文只有空容器；全部清单文字和计数由脚本创建。现有首屏门禁正确拒绝，通用错误却未告诉模型具体原因，导致继续猜测共享状态和文档外壳。目标是让模型一次生成可阅读、可交互的完整内容，失败时根据实际原因定向修复。

## 约束与实现

- 保留 `acceptArtifactOutput` 的现有首屏门禁、严格 schema、SVG/canvas 例外、CSP、脚本与共享状态验收。
- 仅当原验收已经拒绝、原始 HTML schema 合法且满足现有空正文条件时，返回准确的首屏诊断和修复说明；不执行脚本、不补造正文、不用假内容宣告创建成功。
- 生成规则要求初始 HTML 直接写入用户要求的真实标签、初值及控件，JavaScript 渐进增强。修复针对回执指出的问题，同因修复一次仍失败时停止盲重试并保留真实结果。
- 示例清单在 click 事件中提交共享语义动作，避免后续 change 与原生 click 记录重复。共享运行时及既有记录迁移不在本次范围；已有 onchange 复选框的重复回放问题单独记录。

## 验收

- 以真实三份合成检查清单 artifact 回放，全部继续拒绝且收到精确原因。Fixture 不保留请求、账户或会话标识。
- 合法 schema、脚本语法错误、SVG/canvas 例外及现有原生/结构化组件保持原路径。
- 同一份渐进增强清单在禁用 JavaScript 的真实浏览器中显示三个真实标签、复选框及 0/3；通过生产 Conversation 卡片、实际服务/磁盘 Store 勾选、取消及冷重开，保存状态为 `[false,false,true]`、计数 1/3，重开不新增写入，不写入 Canvas。
- 仅运行直接相关合同、策略、HTML 状态、Browser 和类型检查；不构建或操作共享客户端，不改 SDK 或集成清单。
