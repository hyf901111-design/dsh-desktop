# 首页技能输入与窄窗修复

用户要求：技能标签左右留白一致；允许连续选择多个技能；窄窗无滚动条且不截断运营卡片；调查清空预填后整个系统鼠标不能移动。

## 技能引用

- 原技能沿用文件引用164px占位，形成多余右侧留白。技能单独按13px实际标签宽度加左右各6px生成字体占位；仍使用一个UTF-16代码单元，底层草稿仍为U+FFFC。文件164px、选中184px不变。
- 私用区标记避开真实草稿中的私用字符，原生拷贝、输入、IME和选区仍使用canonical草稿。字号/尺寸/字体就绪后重测，旧FontFace在卸载时清理。
- 原生菜单每次传入新draftRev；旧composer错误要求命令前缀为空，误拒已有技能。移除此限制，保留范围、命令token、draftRev、会话/权限检查。允许不同技能；同ID复用，重新选择时刷新旧revision/alias/label，并原样保留正文、其他引用、图片和用户去掉的空格。
- 预填聚焦仅在原生引用占位位置接受私用区投影，用户真实私用文本仍逐字匹配。

- 清空卡片预填：隔离真实InputBar与全桥链路的Meta+A/Backspace、Delete、先删正文再删标签均未复现pointer lock/focus loop；正式客户端同一路径清空后仍可操作。用户确认是系统指针；结束本工具鼠标自动化后，用户回复“现在不会锁住”。不把这一结果写成客户端鼠标锁修复，也不在无根因证据时加入系统鼠标解锁代码。最终验收结束自动化控制，交由用户单独操作。
