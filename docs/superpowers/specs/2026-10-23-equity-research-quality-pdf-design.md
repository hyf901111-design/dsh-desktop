# 研报完整性与默认 PDF 修正

用户已明确要求：修复首次安装补丁顺序和三个 CSS 测试；保留易方达配色；研报恢复此前深度和完整性；任务默认同时生成 HTML 与 PDF。本轮沿用已授权路线自主完成，不重复选择确认。

根因：上轮将仅十二事实的技术验收包当作最终研报展示；正文结构可空，未校验研究范围；PDF仅写为用户另行要求，CLI没有导出能力。安装及CSS由独立功能分支修复。

方案：继续使用模型研究与写作、程序取证和计算的分工。新增 full/brief 报告范围，完整研究按稳定章节kind声明已支持、部分支持或缺失，并要求缺口影响和补充动作；核心论点连接证据、推论、假设、反证和观察。保留数字token校验；受控扩展费用/资产负债指标，原文观察独立核验并引用。按比较目的显式配置表图，自动历史图不混合全年与半年。该检查不评判经济因果或专业签发，也不以字数图表数凑完整性。

默认run生成HTML并调用已认证loopback宿主打印为PDF；宿主接收自包含HTML，不接受文件路径，隔离无脚本无网络渲染，输出有限大小PDF。CLI核对PDF头、长度、摘要后写新文件，manifest分别登记成功/失败及哈希。显式format=html仅供用户选择或开发测试。PDF失败保留HTML和失败记录但非零退出，不声称双格式完成。

茅台示例从已有正式披露原件重新登记更多成本、费用、资产负债和业务资料，复核原文、输出与页面；没有核验价格/同行和金融资产桥接时不强制恢复旧的条件DCF目标价。未覆盖最新公告明确保留缺口。

替代方案：只加提示词不能确保PDF生成，复制旧报告会绕过证据台账，新增外部打印依赖增加安装负担；因此复用客户端Electron及当前结构化证据引擎。
