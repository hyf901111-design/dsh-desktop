# 三个首页用例的自然演示

用户已明确要求直接推进优化，按既有原生界面实施，不另行引入设计确认门槛。

三个用例均应像用户在产品中操作：看板逐步加入组件、逐条连接、搜索新标的并整理；笔记聚焦写入、打开严格挑战、等待检查、读标记和建议再替换；PPT 添加附件与技能、输入一句自然需求、发送、阅读 AI 阶段回复，最后点击交付卡在右屏预览。

PPT 需求示例：“帮我把这份研报整理成一份公司风格的汇报PPT，20页左右，讲清主要观点并配上关键图表。”回复可以重新模拟，不要求复刻原生成轨迹。已有20页成稿、原报告、品牌、日期与来源保持不变。示例身份保留在入口与会话标题及元数据中；不在输入框底部或回复中反复解释离线、预置、回放。不得把历史数据说成实时行情。

保留现有真实工作区、编辑器和会话运行链，不改成静态截图/视频。单纯延长旧固定停留仍会留下动作瞬现；重新制作整套假客户端会破坏保存和继续编辑。因此采用真实操作演员、统一虚拟指针和统一暂停时钟。

共享指针是 DOM 箭头，不控制系统鼠标。现有 `sherlock:home-guide-cue` 增加 `requestId`、`action: move|click|drag`、可选 `fromTarget`；目标为当前真实 DOM 节点。指针完成移动、按下/释放后发 `sherlock:home-guide-cue-reply`。演员收到确认并再次检查所有权、目标存活、暂停和取消后，才执行唯一一次真实点击/输入/工作区更新。连线先逐条演示端口间轨迹，再提交现有真实工作区连接，不点击会触发断开的输入端口。

播放期间只有轻量悬浮暂停、重播、退出控制，不保留大块标题、步骤、说明面板，不挤压输入框高度。过程说明转为屏幕阅读器状态；故障仍明确可见。完成后退出覆盖层并保留产物，重播另建副本。

动作时间用于移动、输入、思考和阅读，不堆叠相同固定等待。指针移动约280–620ms，点击按下80ms/释放160ms，连线700–900ms。笔记检查至少约2s，优化约1.7s；PPT 首答前约2–3s、阶段之间约1.2–2s。阅读停留由共享控制器统一。暂停、窗口隐藏、切换会话、退出与重播均不得导致迟到点击、输入或保存到错误工作区。

验收覆盖三用例实际播放、虚拟箭头与操作先后、AI 忙态/流式回复、无多余说明、暂停/取消、窄窗口，以及退出并重开仍能继续使用已保存产物。正式客户端只能从干净 main 经本地构建手册启动；仅跑直接相关聚焦检查，不升版本或对外发布。
