# 工作台共用数据与组合视图

目标：避免同一工作台的组件分别虚构共同记录，并减少为筛选、详情、两项对比和排序反复生成 JavaScript 的成本。用户仍用业务语言提出需求；组件数量、领域、真实/模拟性质和交互要求不变，不固定整套工作台模板。

当前证据：古籍演练的三卡对同一册的时段、含水率、验收结果互相冲突；自定义对比 CSS 列宽重叠；排序脚本曾保存无法绘制的状态。状态保护已交付，原需求重试140秒仍超过120秒，包含一次语法修复。

新增可选路径：工作台提供 sharedDatasets，每份含 id、label、asOf、note、fields:[{key,label,unit?}]、records:[{id,...字段值}]。共同数据只定义一次，编号唯一，字段/单位/空值必须保留。字段值允许字符串、有限数值、布尔、null及字符串数组。记录/字段/字节容量显式拒绝，绝不截取。第一版仅接收明确模拟工作台；真实资料继续沿现有来源核验路径，不能转换为模拟。

面板 type=view 使用 view:{dataset,filters?,details?,reorder?,navigation?,layout?,sections} 引用共同数据。sections 可按任务组合 records（指定列）、compare（指定对比字段）、schedule（指定label/start/end/owner/detail字段）。navigation为flow或tabs，layout为stack或split。标题、独立筛选栏、正文、点选详情、备注分别布局；窄框叠放，表格默认单行并横向滚动，操作列可见，日期与标签不互相挤压。不缩字，不给无明确连接能力的组件添加节点。

客户端验证字段引用并生成 view artifact:{version:1,type:'view',title,dataset,view}。dataset为校验后的完整快照，面板之间不重新填值。列表、对比、排期、备注直接读取快照，单位/来源说明就近展示。筛选、选中、比较对象和优先级排序通过现有 sherlockShared SDK 保存语义状态；render必须恢复控件值。排序只改变当前面板本地展示顺序，不改变共同事实或其他卡的数据。缺失排期显示待定，不删记录；排期重叠可见标注，不替用户重排。

已有 HTML 路径保留用于这些组合无法表达的交互。已有原生金融、图表、任务等模板保留。组合视图使用现有控件/主题规范，作为新产品扩展，不宣称有独立Figma源节点。

验收：同一份8册演练数据生成档案/对比、资源排程、复检优先级三种不同内容视图，无逐卡模型调用；每卡ID/负责人/时段/数值来自相同快照；任意两项比较、筛选、上移下移、选中详情、重开状态一致；四主题及窄/宽尺寸不重叠。通过实际生成工具边界、隔离浏览器和最终本地客户端验证。源代码/测试通过不等于整项目完成。
