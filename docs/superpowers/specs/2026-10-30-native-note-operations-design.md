# 原生笔记操作与表格交互

## 用户目标

空格输入是当前笔记位置的创作与编排入口；右侧对话是同一份笔记的操作入口。AI 应优先使用笔记已有的可编辑段落、表格、列表、代码等结构，只有确实需要交互展示、行情或特殊视觉时才创建研究组件。不能把普通表格默认制作成不可编辑的研究卡片，也不能要求用户掌握返回协议。

当前可复现例子：`创建一个8乘8的表格` 经组件子任务耗时约两分钟，结果不可编辑。笔记已有的原生表格默认列宽120px，8列超过正文宽度；原生行列把手、整体尺寸控制和菜单可见性也需改善。

## 产品规则

- 明确的空表结构请求直接创建原生表格；`8×8` 指8行、8列共64个可编辑空单元格，不擅自添加行列占位文字或额外表头。需要填充内容、分析、图表或交互的请求继续正常规划。
- 空格在触发的空白行原位插入；侧栏优先使用用户明确目标、选区及保留的笔记插入点。已失效目标不能偷偷改成文末。
- 两个入口共享原生操作执行与保存机制。自然语言内容不受词表限制；确定性快路径仅识别完整且明确的结构指令。
- 复杂请求可组合文字、表格、代码、图片与组件。原生编辑和组件能力各自用于适合的内容，不限制请求表达。
- 原生操作需支持读、插入、更新、移动、删除，以及精确撤销；操作对象是当前已授权笔记中的真实块，不猜测跨会话ID。
- Space 需求框只收需求。结果在正文显示，单行反馈给出简短结果、撤销与确认；点击其他段落按现有规则确认。侧栏给简洁操作结果和需要的内容预览，不输出内部提示词、协议或长篇推理过程。
- 修改与编排复用原位审阅机制；撤销仅回退本次仍拥有的修改，保留后续人工编辑。保存、关闭重开和导出都应使用真实文档。

## 共用操作接口

沿现有 client capability registry → Main adapter/bridge → Notes editor lease 接线，不建立第二条不受保护的通信通道。

- `notes.blocks.read`：读取当前允许范围的块、父级、顺序、修订，返回本次读取的快照身份。
- `notes.blocks.apply`：提交与读取快照绑定的 `insert/update/move/remove` 批次；插入内容为受支持的原生笔记结构。
- `notes.blocks.undo`：使用真实 actionId 与当前读取快照撤销；不调用全局键盘 Undo 代替精确归属检查。

共享执行器在写入前核验 owner/session/document/generation、读取范围、修订/文档指纹、Yjs块身份及插入锚点。整批预检，一次事务，真实保存确认。保留现有4MiB、1万块、取消和权限门禁。重复请求不能重复插入；移动必须记录顺序/父级，不能只依赖内容差异。

## 原生表格交互

- 新建表格根据正文可用宽度设置持久化 `content.columnWidths`；普通8列应在正常正文宽度内清楚显示。用户已有列宽保持不变。
- 提供清楚的“表格／行／列”入口，复用原生增删行列、行列移动及单列拖宽；不能用单纯缩放文字解决溢出。
- 提供“适应正文”“平均分列”和整表宽度控制；支持拖动、键盘，拖动结束一次提交、取消不保存、一次撤销恢复。
- 小窗口使用表格内部横向滚动，单元格行高随内容增长。菜单使用专属顶层与正确编辑器焦点登记，外点/Escape/切换场景可关闭，不能被正文裁切。

## 验收

1. 两个入口分别输入普通8×8指令，得到原生可编辑表格；模型及组件子任务调用数均为0。已就绪编辑器显示目标1秒内，保存确认单独计时。
2. 手动输入多个单元格，保存、换会话、重开仍可编辑且内容相同；不影响原前后段落。
3. 原生段落、列表、代码、表格可读改移删；批次失败不部分误写，重复请求不重复执行。
4. 旧版本、同ID重建、失效锚点、取消、新用户输入、切换会话或账号、保存失败均不误写或误报成功。
5. 撤销插入/修改/移动/删除保留后来的人工作品；未确认内容和已确认内容按各自既有审阅/保存规则处理。
6. 表格在窄宽视口下菜单实际可点击；整表宽度、列宽、拖动取消、键盘、保存重开正常。
7. 保留已经完成的中际旭创演示、IME与文字兜底、完整9b图表浏览守卫、组件顶栏直接操作与欢迎页修复。

## Native 单元格编辑回归修正

- 正常生成返回完整 `kind=capabilities` 请求时，缺少 `wireToken` 不单独构成失败。仅在本轮主生成、无显式标识、当前能力可用、完整外壳及所有参数通过严格校验时兼容；错误标识、混合外壳、代码示例、资料原样回声及格式恢复新增的操作仍拒绝。能力目录、当前账号/文档、修订、取消与真实保存确认保持原约束。
- 原生表格读取结果经 JSON 往返后，自动列宽的 `undefined` 会变为 `null`。编辑已有表格时按自动列宽恢复，保留手工列宽、表头、单元格样式和其余内容；不得借单格修改重新分配整表列宽。负数、非有限数、错误列数仍在事务前拒绝，撤销继续只回退本次实际修改。
- 使用真实失败公开返回重放侧栏读取→修改→保存→撤销→重开，逐块比较公司表以外的正文和表格、逐格比较公司表其余单元格；分别覆盖全自动列宽和混合手工列宽。
- 主生成已正常结束、操作内容完整而仅缺 JSON 根对象末尾容器结束符时，可本地补闭；仅允许本轮标识完全匹配且完整目录/参数/资料回声校验通过的能力请求。不得补写字符串、值、字段、缺失元素或接受非空后缀；错误标识和展示代码不取得操作权限。资料中的同类半壳仅用于拒绝回声，不能成为执行来源。
