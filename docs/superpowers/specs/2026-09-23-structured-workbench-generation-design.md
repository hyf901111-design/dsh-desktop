# 工作台组件生成重构：第一阶段模拟数据

## 目标与验收

用户需要更快、更稳定、更省资源且样式统一的组件生成。第一阶段只处理明确标为模拟的数据和信息；真实数据获取及来源校验仍走现有流程。以六面板贵州茅台演示工作台为验收案例：规划模型只调用一次 `research_workbench_create`，每个面板提交紧凑的 v1 数据对象，宿主生成成品，不再启动六个独立模型子任务。组件内容、日期和标题显著标为模拟；任何无效面板使整份模拟规划被拒绝，不留下半成品。

## 数据流

1. 主研究智能体判断是否为模拟场景，统一构造一套自洽的数据，通过工作台工具提交 `dataMode: simulated` 和每个面板的 `artifact`。模型负责内容与数字；宿主负责样式和交互实现。
2. 宿主校验规划、数据对象、容量及模拟标识。第一阶段只接受现有受控格式：`chart/table/kpi/dashboard/news/reports/calendar/market`。拒绝模型提交的原始 HTML、脚本和自造链接。数据模板转换为既有 v1 组件协议，并使用现有验收器验证结果。
3. 任务服务以一次持久化写入创建全部已完成的面板任务，不占模型子任务槽位、不做每面板重试。现有画布仍通过 taskId 获取结果，沿用完成态布局、主题、放大阅读及持久化机制。非模拟规划及手动创建沿用旧路径。
4. 工作台计划存储原始、已校验的数据供幂等重试；给画布的列表响应只返回展示与任务标识所需字段，避免重复传输整套数据。

## 失败边界

校验先于画布计划写入。数据不完整或模板不支持时，工具返回具体字段错误，主智能体可修正同一请求后重新提交。任务存储写入失败时回滚内存任务，计划保留为可诊断的未就绪状态。应用重启后仍可从已完成任务记录恢复内容。模拟路径不会访问行情接口或产生外部链接。

## 后续阶段

真实数据阶段复用同一数据对象和宿主模板，把事实检索、口径与来源绑定到一次共享数据快照；复杂业务交互增加受控模板，避免回退到任意 HTML。共享画板的云端写入与协作一致性单独接入同一已校验产物协议。本阶段不改变共享画板执行协议。

## 验证

聚焦测试覆盖六面板一次提交、无子智能体、无效数据原子拒绝、幂等与重启恢复、旧路径兼容。再从集成工作树构建测试客户端，检查浅深主题、窄宽尺寸、成品字段与标识；记录真实耗时和未覆盖项。用户验收前不晋升 `main` 或发布。
