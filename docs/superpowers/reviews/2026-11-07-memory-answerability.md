# 本地记忆无答案防误用验证

2026-11-07。技术门槛通过，接下来接入服务与真实客户端；本报告不是产品构建验收。

## 判定设计与取舍

第一轮本地 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` INT8 重排未通过：在原始 46 题校准集，阈值 0.1 时正例 90%、无答案误用 4/6；阈值 0.99 时正例仅 45%、仍误用 1/6。它衡量相关程度，不能可靠判断所问属性是否存在。未对独立集继续调阈值，不将此模型接入产品。

改为保留 SQLite/向量本地检索，由当前会话模型进行受限证据选择。输入只包含问题和已授权候选；输出只能为 supported 与现有 ID/原文引用。代码核对 ID、修订、逐字引用、数量和完整预算；不接受模型补写事实。无工具，失败、无依据、格式错误、超时均不注入。当前请求优先于记忆；最终注入完整原始条目，保留否定和条件。

这项判断使用用户已配置的会话模型。若该模型在云端，会发送候选记忆供核对；本地存储/语义检索不等于完全离线处理。产品设置中必须说明该用途。

## 冻结数据与结果

- 1,086 条合成记忆：此前 1,066 条，加 20 条新实体“雾川”的办公事实。
- 原始 46 题：40 正例、6 无答案。独立 64 题：此前新集 20 正例/4 无答案，加新集 20 正例/20 无答案；新集 SHA-256 `4b46b360bd67cf8d51916ca7cc7864e88736ad67dab039ea61a070d2d9683ce7`。
- 新负例包含同人缺电话、联系人冒充法人、政策冒充实际经营数字、未发布状态冒充确定日期、缺少房间楼层/版本/编号等属性，以及要求忽略无依据的指令夹带。
- 使用现有默认 `zai/GLM-5.3-Flash`，关闭额外 thinking，temperature 0；调用凭据从既有本地安全配置读取，未写入日志、源码或证据。
- 原正例完整 top-5 来源命中 **38/40（95%）**，独立正例 **40/40（100%）**；全部 **30/30 无答案不注入**；110 次模型调用失败 0。
- 独立集证据选择延迟 p50 **1.19 秒**、p95 **2.25 秒**、最大 **6.47 秒**。这部分单独测量，尚非完整客户端响应时间；本地查询、IPC 与聊天生成另算。
- 4 项证据契约聚焦测试通过：未知 ID/伪造引用/重复引用拒绝，unsupported 强制为空，完整否定条目保留，1,200 UTF-8 字节约束。

## 限制与产品要求

一次固定模型/合成集不能证明所有模型与任意问题均不会误选。正式运行仍需失败关闭、来源与版本复核，以及真实账户切换/删除/重启验收。采用 8 秒证据选择超时，超时本轮不注入；同一问题和修订下避免每个工具步骤重复核对。

检索候选通过核对之前不能出现在可被旧版 runtime 直接注入的 `block` 中。主进程返回候选、运行时核对并打包；提交前再次验证 ownerEpoch/scopeEpoch/revision。

证据：仓库外 `local-memory-product/relevance-minilm/relevance-results.json` 与 `local-memory-product/evidence-model/evidence-results.json`；可复现脚本为 `experiments/local-memory-spike/{relevance-benchmark,evidence-benchmark}.mjs`。当前模型 API 原始输出仅来自合成题目。

## 产品实际推理配置复测

适配器能力声明中 GLM 5.3 只提供 low/high/max，因此产品不强行发送不支持的 off。选择可用的最低推理档（优先 off，否则 low），temperature 0；有推理模型给 2,000 输出 token，8 秒独立硬截止。对不响应取消的适配器也可按时退出，且不会接纳迟到结果。

以产品的 `thinking=enabled, reasoning_effort=low, max_tokens=2000, deadline=8s` 重新运行原封不动的 110 题两轮：

| 指标 | 第一轮 | 第二轮 |
| --- | --- | --- |
| 原始正例完整命中 | 37/40（92.5%） | 37/40（92.5%） |
| 独立正例完整命中 | 40/40（100%） | 39/40（97.5%） |
| 无答案未注入 | 30/30 | 30/30 |
| 格式或超时失败 | 1（q01 JSON 不合法） | 1（q06 超过 8 秒） |
| 独立选择延迟 p95 | 2.09 秒 | 1.60 秒 |

失败计入漏召回，不剔除，均失败关闭。旧 benchmark 的 `pass` 同时要求零 API/格式失败，因此这两份报告严格标记为 false，不能称为全调用成功。产品接入依据是两轮均满足已定“正例 ≥90%、无答案误用 0”的功能门槛，服务可用性实测 218/220，保留约 0.9% 本轮跳过记忆的限制。此为本地测试候选，不承诺所有模型质量，也不宣称全链路只需几毫秒。

复测证据分别保留在仓库外 `local-memory-product/evidence-product-config/evidence-results.json`、`evidence-product-repeat/evidence-results.json`，未覆盖先前报告。

## 产品代码复核与聚焦验证

一次独立复核发现并修复三项重要问题：大批量首次索引超时重启、自然过期记忆被同轮缓存继续注入、关键词候选错误套用旧全局字节预算。每项都先复现失败，再修正并通过覆盖测试；修正后 11 个直接相关记忆文件共 116 项测试通过，typecheck 通过，未执行全功能单元测试。

索引改为后台可取消建立，期间立即返回关键词候选并继续受依据核对保护；每 128 条保存加密缓存进度。独立账户、状态与项目过滤保留。500 字级长记忆不再拖住聊天调用，最终校验重新检查到期时间与来源修订。

实际产品 worker 对 919 条合成记忆测得首次建立 7.25 秒；暖查询 p95 单并发 4.95ms、3 并发 12.35ms、10 并发 36.82ms，分别为 3/9/30 次样本。进程峰值 RSS 739MiB，空闲两分钟释放；这是小样本本机结果，不是服务端容量或完整聊天响应时间。界面使用生产 view/style 在 Chromium 验证浅色/深色与 1160/720px，无横向溢出，独立开关与新增编辑正常。最终 Electron 实包验收另行记录。

## 实包发现的进程通信兼容性修正

首个本地包在真实 Electron 进程中出现语义检索回退，而直接用 Node 启动同包 worker 正常。定位为 Electron 与内置 Node 的 V8 序列化版本不兼容：`serialization: advanced` 导致子进程报 `Unable to deserialize cloned data due to invalid or unsupported version`。这说明单独启动 worker 不能替代宿主链路验收。

消息全部为普通对象，向量缓存已编码为 base64，因此跨进程协议改为 JSON。新增以真实 Electron V8 启动产品 LocalMemoryEngine、连接内置 Node/实际模型的自动回归：修正前 fallback 失败，修正后索引、缓存返回和中文查询通过。此次直接相关的 67 项测试及 typecheck 通过；最终包须重新构建并再验收。
