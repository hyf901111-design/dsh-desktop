# 本地记忆无答案防误用验证

2026-11-07。技术门槛通过，接下来接入服务与真实客户端；本报告不是产品构建验收。

## 判定设计与取舍

第一轮本地 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` INT8 重排未通过：在原始 46 题校准集，阈值 0.1 时正例 90%、无答案误用 4/6；阈值 0.99 时正例仅 45%、仍误用 1/6。它衡量相关程度，不能可靠判断所问属性是否存在。未对独立集继续调阈值，不将此模型接入产品。

改为保留 SQLite/向量本地检索，由当前会话模型进行受限证据选择。输入只包含问题和已授权候选；输出只能为 supported 与现有 ID/原文引用。代码核对 ID、修订、逐字引用、数量和完整预算；不接受模型补写事实。无工具，失败、无依据、格式错误、超时均不注入。当前请求优先于记忆；最终注入完整原始条目，保留否定和条件。

这项判断使用用户已配置的会话模型。若该模型在云端，会发送候选记忆供核对；本地存储/语义检索不等于完全离线处理。产品设置中必须说明该用途。

- 新负例包含同人缺电话、联系人冒充法人、政策冒充实际经营数字、未发布状态冒充确定日期、缺少房间楼层/版本/编号等属性，以及要求忽略无依据的指令夹带。
- 使用现有默认 `zai/GLM-5.3-Flash`，关闭额外 thinking，temperature 0；调用凭据从既有本地安全配置读取，未写入日志、源码或证据。

## 限制与产品要求

一次固定模型/合成集不能证明所有模型与任意问题均不会误选。正式运行仍需失败关闭、来源与版本复核，以及真实账户切换/删除/重启验收。采用 8 秒证据选择超时，超时本轮不注入；同一问题和修订下避免每个工具步骤重复核对。

检索候选通过核对之前不能出现在可被旧版 runtime 直接注入的 `block` 中。主进程返回候选、运行时核对并打包；提交前再次验证 ownerEpoch/scopeEpoch/revision。

证据：仓库外 `local-memory-product/relevance-minilm/relevance-results.json` 与 `local-memory-product/evidence-model/evidence-results.json`；可复现脚本为 `experiments/local-memory-spike/{relevance-benchmark,evidence-benchmark}.mjs`。当前模型 API 原始输出仅来自合成题目。
