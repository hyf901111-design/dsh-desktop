# PPT 与 PDF 文件卡片登记

`presentation_files` 是宿主的只读文件交付登记，不制作文件，不代表质量门禁或 PowerPoint 原生验收通过。它补足由 Python/Bash 保存二进制文件、没有编辑器 mutation 事件的交付路径。

当前用户主会话保存文件后，明确调用一次：

```json
{"paths":["outputs/报告.pptx","outputs/报告.pdf"]}
```

`paths: string[]` 为必填项。所有请求的成品均已核验时可传 `complete: true`，宿主在成功登记后结束本轮，并在最后一条回复下展示文件。可以单独登记一种格式，最多一个 PPTX 和一个 PDF。路径相对当前已注册工作区或位于该工作区内的绝对路径；不扫描目录、猜测文件名或选取旧稿。明确指定的已有文件可登记，不设置“必须刚生成”的修改时间门槛。

宿主核对当前真实用户轮次、主会话、账户与运行期、已注册工作区和文件策略；校验普通文件、真实格式、大小与读取期间的文件身份。已注册工作区根可以规范化系统别名，但文件或子目录的符号链接、路径穿越和工作区外文件仍拒绝。成功回执为 `kind: ework-presentation-files`、`status: available`、`qualityVerification: not-evaluated`，含路径、格式、字节数和 SHA-256。Native 和 Code Mode 的可信工具回执都可在闭轮尾部恢复文件卡片；普通 Bash 打印同样 JSON 不产生登记事实。

工具失败不能冒称交付完成，也不应反复制作已有成品。质量存在待复核项时，保留真实质量说明，不删除待验收文字以换取卡片。卡片沿用现有文件可用性检查与 PPT 批注候选门禁。

旧宿主没有该工具，或当前是目标模式的自动续轮（`source.kind: goal`）时，不安装工具、不重试调用；在最终回复中列出实际保存文件的精确 Markdown 链接，例如：

```markdown
[PPTX](<outputs/报告.pptx>)
[PDF](<outputs/报告.pdf>)
```

自动目标轮的授权扩展不在此最小登记能力范围内。最终精确链接、原有文件编辑事件、研报回执和私有演示交付路径继续独立工作。

已保存历史回复中的 `## 交付文件` 标题不再要求冒号；独立质量章节中的原生复核待完成状态不抹去明确列出的文件。明确撤销交付、尚未完成的文件或候选草稿仍不自动提升为成品卡片。
