## 产品行为

普通会话只注册 `financial_query`。模型根据用户的问题填写查询意图，用户无需知道服务名称、选择数据源或配置金融数据密钥。混合问题分成行情、净值或研究子查询。名称有歧义时展示证券名称及代码进行确认，不凭名称猜代码。

| 查询 | 默认路由及已实现范围 |
| --- | --- |
| 股票、指数、ETF 最新行情 | 同花顺；逐证券取时间戳，避免批量最新时间冒充每只证券的行情时间 |
| 股票、指数历史行情 | 同花顺；日、周、月；最多请求一年，返回最近 35 根完整 OHLC，超过明确标记截断 |
| ETF 历史交易行情 | 同花顺；日线 |
| 基金单位净值、基金资料 | 盈米优先；同花顺仅作经过标的、币种、净值口径检查的备用源 |
| 复权净值 | 同花顺；明确标记“复权净值”，与累计净值分开 |
| 单基金、同日对比、持仓风格、近期变化 | 盈米，沿用已验证的标准化证据适配 |
| 扩展基金研究 | 盈米的受控能力目录及实际账户参数校验；服务端仅输出已映射业务字段 |
| 证券名称查询 | 股票、指数、ETF 使用同花顺；场外基金先尝试盈米的实际搜索参数，再用等价名称代码检索 |

ETF 净值即使由盈米主路由返回，也要使用证券元数据核对完整交易所代码、ETF 类型及 CNY 币种；六位基金代码本身不能证明交易所。如果主路由已报权限或额度错误，不再请求其他源。上游已明确标记过期的净值保留过期状态，并在允许范围内尝试日期更合适的等价结果。

分钟线、累计净值和货币基金收益指标尚未建立经过验证的本功能映射。收到此类请求返回能力缺口，不能改用日线或单位净值冒充。目录中的“可用”表示账户提供该能力，不代表数据已核验或业务字段已全部映射。扩展研究中的自由文本、来源链接及未映射字段不直接交给模型；展示数据暂缺或口径尚未核验。

## 实际执行入口

- `packages/dsh-fund-research-runtime/financial-tool.js`：普通会话入口和自然语言调用说明。
- `packages/dsh-fund-research-runtime/financial-contract.js`：请求与公开结果的严格校验。
- `services/fund-data/financial/policy.js`：实际加载的服务端默认路由策略。
- `services/fund-data/financial/router.js`：选源、标准化、时效判断、有限备用查询。
- `services/fund-data/financial/projection.js`：业务字段白名单和旧客户端入口的信息隐藏。

继续使用已登录账户的本机桥接及 `/v1/fund-research/query`，新增请求 `operation: financial`。服务端认证、用户/IP 限速、并发控制和持久化每日预算均在路由之前执行。一个上游的故障冷却不会阻断另一个数据源的金融查询。

只有已确认的网络故障、上游 5xx、缺字段或所需日期不满足可触发一次等价备用查询。权限、额度、错误参数、取消或无法分类的错误不触发切换。备用结果不拼接成另一来源的时间序列，不用较差日期替换较好的主结果。

行情不复用基金研究的十分钟缓存。金融查询结果不写共享缓存；公开证据使用随机标识，服务端保存来源、数据摘要哈希和日期用于追溯，不保存查询参数或行情值。追溯记录在 24 小时到期后通过 Durable Object alarm 后台清理，每批最多 64 条；请求只写记录和到期索引，不扫描历史记录，清理不依赖后续用户查询。查询之间共用应用每日预算；同一查询内部有界调用多个只读接口。

实时状态需要证券自身行情时间以及覆盖当日的交易日历。连续交易时段以 60 秒为产品时效目标；这不是供应商 SLA。午休、收盘后及开盘前根据最近一个完成交易时段的结束时间检查，不能仅凭日期相同就把上午的旧行情标成收盘行情。日历不确定、缺少数据时间、休市或超过目标时明确标记。净值只标真实净值日期，未核实披露日历时不会称为今日最新或断言“今日尚未公布”。

公开结果及旧版研究入口都会移除供应商说明、接口地址、请求标识、原始错误、来源链接和未审核文本；保留合法证券名称，例如股票“同花顺”。会话进度显示“正在查询股票行情”“正在获取基金净值”等业务文字。

## 凭证与启用顺序

共享密钥只放在现有金融服务的云端 secrets：`YINGMI_API_KEY`、`TONGHUASHUN_API_KEY`。安装包、路由策略和源码不含密钥。客户端只携带自己的应用登录凭证，不需要同事把金融密钥编译进安装包。

维护同事可直接按[密钥配置与启用说明](financial-routing-operations.md)操作；本机钥匙串凭证不会自动同步到云端，云端配置一次即可。

合并验收后，先由服务维护者在正确的现有云账号配置同花顺 secret，并部署服务端，再构建/分发客户端。客户端配置会停用此前本机直连的 `sherlock-tonghuashun-mcp` 实例。只有服务端部署完成，安装包中的统一入口才能访问新请求协议；旧的基础基金研究请求仍兼容。

本次未部署云端、未替换共享客户端、未发布安装包。功能工作区交付源代码及检查证据，后续按项目多会话集成手册进行验收合并。
