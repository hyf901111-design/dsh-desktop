# 组件生成重构工作记录

目标：理解需求 → 收集/解析内容 → 可视化交付；不以样式或模板容量阻断已经取得的内容。成功率 ≥90% 是实际客户端验收目标，未完成的内容不能计为成功。

## 已确认问题

- v103 已缩减常驻提示词，但最终交付仍依赖大量模板协议与串联校验，不能视为完整重构。
- 原纯债测试的图表有 8 条数据，但辅助表的名称列不在第一列导致拒绝交付。这是可无损归一化的呈现问题。
- 工作台准备阶段还没有 task 时，前端误报生成组件失效；恢复监听又从错误时间起查任务，导致状态不同步。
- 风险数据不足的卡不能靠空壳、虚构指标或单只错误类别基金标记完成。

## 本轮实施边界

1. 内容与呈现分离：增加简单的内容交付入口，普通回答、记录、来源是输入；客户端承担呈现编译与降级，旧协议兼容。
2. 无损恢复：结构正确的数据因图表格式或容量不适配时保留完整数据交付可读表格；无法确定关联关系时不能按位置猜测。
3. 故障分类：安全、真实性、缺失内容继续明确处理；呈现问题本地修复，避免重复取数和无穷模型重试。
4. 生命周期：计划准备、排队、运行、部分交付、完成、失败各状态一致，恢复监听不误杀任务。
5. 聚焦验证、中文本地提交、通过集成通道打包。真实客户端测试以原纯债需求及其他资料/层级/表格场景记录结果与耗时。

- 修复阶段保留当前子任务拥有的本地只读数据；网络研究预算仍受限。读取工具到整个子任务释放时才关闭，避免有数据却无法继续交付。

## v106 实包与补充修复

同一客户端模型用原请求各发一次。模拟项目最终 4 张卡，耗时 461.6 秒，32 条明细的分页、搜索、部门筛选和来源在界面验证通过，前一份错误计划仍留有 3 张失败卡。Word 文档 10 张卡中 5 张完整、1 张部分、4 张失败，耗时 620.6 秒。版本对比 4 张卡结构完整，耗时 577.2 秒，但最新正式发布被替换成主、次版本，业务范围不合格。回查 v105 的 3/3 也只代表结构完整，Vite 当时漏了同期发布的维护版本。纯债主会话拿到 8 只基金共 2,303 条净值，超过 25 分钟仍未生成卡片，提交分别遇到原始记录与聚合冲突、正文格式和共同数据引用限制。

4 张文档卡在 SDK 启动阶段因把子会话局部工具传给全局白名单而失败。修复后使用真实 SDK 验证局部读取工具在首轮和修复阶段均可用。同步修复静态指定源重复取数、默认筛选掩盖清单短缺、固定模拟样例占用请求标识、附注及键值表格形状导致的整板返工。

对 8 份真实净值响应离线回放，模型侧表示从 281,827 字节降至 106,529 字节，完整保留 2,303 行及来源、字段、空值、分页。该结果是响应体积变化，实际 token、用时与完整成功率需看后续实包。
