# 画布持续任务生命周期

任务 ID 是持续执行的单位，模型单轮调用仅是其中一步。等待外部用户、组件变化、用户拖动画布以及临时窗口切换，都不代表用户取消任务。无需为具体组件或游戏写专用逻辑。

## 恢复与退出

- 每次重试先获取最新观察，不重放旧坐标或旧点击。保留 requestId 收据、已消耗操作次数、进度历史和任务 ID；未知操作结果必须先核实。
- 临时忙碌、陈旧观察、短暂失焦或断线、单轮模型超时和非法状态输出进入 waiting。退避 750ms 至 10s，组件变化信号可以提前唤醒观察。
- 成功获得有效一轮决策才清除故障恢复计时；仅观察成功不能掩盖连续模型失败。连续 5 分钟无法继续时暂停，并说明原因。正常等待外部变化不计为故障。
- 不可见时不执行画布动作；返回同一画布后自动重新观察。权限撤销、用户主动停止/暂停、客户端退出，以及任务明确时长/动作上限仍然生效。
- 单轮模型最长 120s，且不得超过任务截止时间或故障恢复窗口。单轮取消先撤销该子执行器权限，清理后才开始下一轮。
- 全任务取消信号与单轮超时信号分离。输入框停止按钮只停止当前活动任务，不改写历史暂停任务。取消后旧响应和旧 guard 不能再次操作。

## 会话表现

启动模型调用和后续持续轮次复用一个可展开执行过程，进度回报留在发起消息所属区间。原生 turn-tail 的复制/反馈等结束操作延后到持续任务实际结束以后，不能夹在启动回报与后续任务之间。普通对话不受影响。协作会话使用同一个合并函数；短时收不到执行端心跳显示等待连接，不能伪造“已暂停”。
