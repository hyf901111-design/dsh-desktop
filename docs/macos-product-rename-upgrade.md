# macOS 产品改名更新

2026-09-08 的 ShipIt 日志确认：0.9.0 → 0.9.1 安装将 Sherlock.app 改为 EWork Odyssey.app 后，仍使用旧目录的 Squirrel.framework/Resources/ShipIt 执行二次启动，触发 posix_spawn ENOENT。安装成功与自动重启成功是两个不同阶段。对应上游问题：https://github.com/Squirrel/Squirrel.Mac/issues/325 。

更新管理器在原生 update-downloaded 后、quitAndInstall 前读取该应用的 ShipItState.plist，校验当前安装地址、Bundle ID 与已下载版本；仅在最终路径变化时启动独立保护进程。辅助脚本复制到临时目录，由已启动的内置 Node 执行并完成 IPC 就绪握手，再允许原应用退出。它等待原进程结束，核对最终地址的版本、CDHash 与完整代码签名，留出原生重启时间；如果该精确目录没有主进程，则通过系统 open 使用最终绝对路径启动。失败、超时或原生安装同步报错均不启动未经验证的包。

旧 Dock 地址仅在旧路径消失、新路径处于同一目录且 Bundle ID 匹配时修复，保留入口 GUID、顺序和其他应用，清除失效书签。修改通过 CFPreferences 完成；只有确实修改时才刷新当前用户的 Dock。新版启动也执行此修复，因此能恢复此前已改名但尚未迁移的入口。自定义安装位置、用户改过名字的包及其他目录副本不会被接管。

保护代码不能回溯运行在已发布的 0.9.0/0.9.1 进程中。已经跨名安装成功但重启失败的用户，首次需打开实际的 EWork Odyssey.app；含本修复的版本启动后可修复旧入口。后续正式发布时不得声称未包含保护逻辑的旧版本已能自动恢复；如要覆盖尚未升级的 0.9.0 首次跨名过程，需另做同名过渡包与更新路由，不能复用或覆盖线上 0.9.1 包。

本次仅做聚焦检查：路径/签名/Dock 条目迁移、安装就绪时序和取消、实际文件改名后的签名验证、辅助进程握手；不上传更新源，不执行旧客户端全量下载升级。
