# Computer Use 三方案实机对比

用户要求：精选三个开源方案，以可切换插件接入；统一使用火山 DeepSeek Flash，按实际场景比较后选择默认实现。

## 候选与比较边界

- Cua Driver 0.38.0，MIT：原生可访问性树、截图和受窗口身份约束的输入。当前产品锁定的是 0.28.2，并且宿主主动禁止网页文本框和同进程多窗口后台输入，不能将这些拒绝直接归因于最新驱动。
- Peekaboo 4.9.8，MIT：macOS 原生语义操作与截图、菜单、文件对话框工具。
- UI-TARS NutJS Operator 1.2.3，Apache-2.0：UI-TARS 开源桌面执行层，截图坐标及前台键鼠。此处评测的是执行层搭配 DeepSeek Flash，不声称等同于 UI-TARS 专用视觉模型的成绩。

来源：
- https://github.com/trycua/cua/releases/tag/cua-driver-rs-v0.38.0
- https://github.com/openclaw/Peekaboo/releases/tag/v4.9.8

## 实现与验收计划

1. 固定发行版本、校验和和许可证。插件中显示三个候选，每次仅启用一个，禁用或切换立即停止旧会话。
2. 保留账户隔离、当前模型图片能力检查、取消和时间预算。所有操作后以新观察确认，拒绝/未知执行结果不报告为成功。
3. 同一模型 `volcengine-agent-plan / deepseek-v4-1-flash-261017`，同一任务内容、工具轮数/时间预算，不给某方案额外模型或人工步骤。
4. 聚焦场景：原生文本编辑与保存读回、网页表单与滚动、Electron 输入、多窗口定位、拖拽、界面变化后的重新定位及取消。使用自有测试数据，独立读取结果验证，不以模型自报完成计分。
5. 记录成功/失败、耗时、工具次数、错误和干预情况；按成功率优先，再比较定位正确性、稳定性和耗时。实际权限不足或模型不可用单独列明，不虚构成绩。
6. 聚焦回归及中文 Git 提交后，通过新集成批次构建本地客户端，保留现有会话与模型配置。不发布、不推送、不升级应用版本。

## 实测结果与选择

2026-11-06，当前 macOS arm64，统一火山 `deepseek-v4-1-flash-261017`。六类场景各两轮，另加一轮系统 TextEdit 真实文件保存。第一轮模型输出预算 2048，第二轮提高至 8192；同轮三个候选预算一致。每个场景上限 24 次模型回复、240 秒，按页面实际回执或磁盘读回判定。

| 场景 | Cua | Peekaboo | UI-TARS 执行层 |
| --- | --- | --- | --- |
| Electron 中文输入、复核、保存 | 2/2 | 2/2 | 2/2 |
| Chrome 表单 | 2/2 | 2/2 | 2/2 |
| 滚动、下拉选择、复核提交 | 2/2 | 2/2 | 1/2 |
| 卡片拖拽 | 2/2 | 2/2 | 0/2 |
| 布局改变后读取并填写新内容 | 2/2 | 2/2 | 2/2 |
| 原生同进程多窗口，目标保存且干扰窗口不变 | 2/2 | 2/2 | 0/2 |
| 系统 TextEdit 修改并保存到磁盘 | 1/1 | 1/1 | 0/1 |
| **合计** | **13/13** | **13/13** | **7/13** |
| 单次平均耗时（含启动和失败） | 27.74 秒 | 24.89 秒 | 46.20 秒 |
| 单次中位数 | 31.32 秒 | 26.59 秒 | 18.52 秒 |

推荐 **Peekaboo**：本组完成率与 Cua 相同，总体耗时略低，包含窗口、菜单与文本语义操作。Cua 为可切换备用；UI-TARS 保留为实验插件，不作为默认。此结论只适用于本机、当前模型与上述场景，不等于开源方案的通用排行榜。UI-TARS 没有使用专用视觉模型，不能将本结果当作该模型成绩；该 Operator 本身的拖拽、文本 trim 和快捷键行为也构成限制。

新账户默认推荐方案；已有明确开关选择保留，防止重新启用用户已关闭的能力。三者互斥，切换、禁用、取消、锁屏及 Cmd+Shift+Esc 会终止旧进程。旧的后台输入限制不再作为这三个候选的宿主默认限制。

逐项计分、输出预算、原始报告文件名及 SHA-256 见 [结果记录](computer-use-bakeoff-20261106-results.json)。本地原始报告保存在功能 worktree 的 `output/computer-use-bakeoff/`，不提交桌面内容。截图仅供当前模型观察，不写入报告。

### 排除与复测

- 初次三条预检的测试页面漏写复核字段，明确排除；修正页面后完整重测。
- 第二轮 Peekaboo 拖拽期间，并行包检查原地改写了正在使用的驱动。macOS 崩溃记录为 `SIGKILL (Code Signature Invalid)` / `CODESIGNING Invalid Page`，与文件改写时间吻合。这条保留并排除，独立复测通过；准备脚本改为原子替换。
- TextEdit 首次预检在任务后的 AppleScript 清理超时，未生成完整报告，未计分；取消该清理后完整重跑三者。任务内容仍完全由同一模型使用桌面工具执行。
- Peekaboo 的部分输入返回 `dispatchedUnverified` 和 `isError`，不等于没有发生输入；保留原始语义，模型重新观察，评分仍只看最终实际结果。

## 集成状态

插件服务、互斥开关、模型工具桥、独立驱动进程、固定发行包校验及许可证已接入。最终共享客户端必须经新集成批次构建；基准程序直接使用同一后端适配层，不能替代打包后客户端的端到端验收。后续客户端证据另行登记。

## 用户真实任务后的重新评估

70ec583a 的用户试用未通过性能验收。“打开豆包，发送 EWork 截图并询问设计意见”在原会话中执行 72 步，约 10 分钟后超时；其中模型约 8 分 28 秒，工具约 1 分 16 秒。此前的 39 项有限测试不能证明此类跨应用任务可用，暂不接受或晋升该集成批次，也不据此前成绩宣布最终选型完成。

定位到应用进程聚焦与主窗口显示混淆、截图再次读取、未确认输入重复尝试及缺少 Dock 唤起和原生图片粘贴入口。本轮补齐允许的入口、截图直接回传、截图坐标约束和投递后的观察，保留原始未知结果语义，禁止自动重发输入。`scripts/computer-use-benchmark/cross-app.mjs` 使用同一火山 Flash 模型，操作专用无用户数据窗口和豆包的新测试对话，截图和工具轨迹仅留在忽略目录；发送结果必须另行目视核验。

上述适配修正不等于端到端任务通过。实测仍发现主窗口截图遗漏独立弹出菜单，纯坐标方案也未完成同一任务，继续比较与定位；不能把运行变短或模型自报成功记为通过。
