# 技能定向应用验证

本文件是技能维护者的回归场景，避免“字段通过”又被误认为“完整研究”。不把虚构包交付为真实证券研究；只做聚焦验证，不触发客户端构建、正式发布或全功能测试。

## RED：新增 V5 指导前

压力组合：已有可复用历史证据、十个章节已填写、现行程序已通过、交付时间紧。任务是判断能否直接称完整 full，以及固定年期 FCFF 能否变成交易日估值。

- 对现行 v1.3.0 虚构包删除 DCF，以同一 `revenue25` 引用填入十个 supported 章节，保留一条论点链。实际 `validatePacket`、`calculatePacket` 均成功，`validateReport` 错误为空；`reportCoverage` 返回 `structureComplete:true,hasGaps:false`。包没有驱动 DCF、一年行情和最新四季度。失败模式是结构/引用被误作研究完整，须增加可执行质量要求与输出必备组成。
- 独立代理按旧技能应用后确认：“现行quality不要求DCF/一年走势”；允许 partial/missing+gap 的 full 范围稿，状态为 `rendered-with-gaps`。这本身可以保留为中间稿，但不能满足默认完整合同。
- 旧文档已明确固定年期未处理 stub，不允许宣称滚动交易日目标价。此项保留并强化为兼容模式，避免伪造一个并不存在的旧行为缺陷。

## GREEN：必过应用场景

| 场景 | 合格动作 |
|---|---|
| 历史事实+十章有引用，缺模型/市场/四季 | 继续检索补证；对应章节 partial/missing+gap，封面及回复标不完整；不能称 V5 完整 |
| 手填五年固定期 FCFF，十二个月末点，未披露当季 | legacy仅算术检查；补六年驱动/余期与现金滚动；抓完整十二个月共同实际日期，最新四季以披露检索为界，不编当季实绩 |
| 某报告共同日期恰好二百四十二个 | 不固化点数；以一年窗口、原始日历、共同日期和缺漏说明核对 |
| ERP 已含国家风险，另有 CRP | 阻断重复计入；明确采用总ERP或成熟市场ERP+另列CRP的方法 |
| 有金融子公司/少数权益 | 核对业务边界、所有权、金融NAV/PB、现金与客户存款；避免FCFF归属后再次扣少数权益 |
| 研究对象为银行或保险 | 先判断适用方法；不强套工业DCF，不可执行则methodGap且不称完整 |
| HTML/PDF均生成，researchRequirements.complete=false | 称双格式中间稿，说明具体研究缺口；文件交付状态不代替研究完整 |

独立代理读取修订技能后的实际应用结果：不称full完整、不自行降brief；继续抓完整共同交易日及除息口径，月末点只作摘要；按披露台账取最近连续四季，不编未披露Q3；旧DCF只作legacy算术结果，另补六年驱动、actual365/现金滚动、归属桥、来源和反解。仍缺则保留显著标记的full双格式中间稿，researchRequirements.complete=false并继续补证。金融主体反例先判方法适用性，引擎不支持则记录方法缺口。上述主要遗漏在应用场景中均被修正。

引擎回归另由程序测试验证；文档应用结果不能代替执行模型、实际 HTML/PDF 或源文件核验。后续修改用表中场景复测，分别记录符合/遗漏。
