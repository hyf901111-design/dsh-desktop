# 研报写作

默认交付符合 [完整研究合同](references/research-quality.md) 的中文研报与同名正式 HTML/PDF。观点由研究形成，事实、经营驱动与数值由证据和程序核对；完整性与文件生成成功分别验收。使用 EWork 当前模型和工具，无需安装 Claude Code 或 Python。

## 在 EWork 中使用

用户从技能列表选择“研报写作”，或输入 `/ework-equity-research 给贵州茅台写一份研报`。自然语言明确要求研报时也可加载。停用后不继续调用本技能。

加载技能时返回的资源目录为 `SKILL_ROOT`，不能猜测为当前工作目录。先读 [运行与输入约定](references/workflow.md)。在客户端使用专用 `research_report` 工具做环境检查、校验和默认双格式生成；服务凭据由客户端内部传递，不经过 Bash，也不让用户配置或复制。资源目录中的 Node 脚本只作为初始化、取哈希和开发检查的工具：

```sh
node "<SKILL_ROOT>/scripts/research.mjs" init --company "贵州茅台" --ticker "600519.SH" --as-of "<实际研究日>" --out "<会话工作区>/research/packet.json"
```

只把技能目录当作只读资源，原文、输入和产物写入当前会话工作区。Node 来自 EWork 当前运行环境，不从网络安装软件。命令长耗时则使用可用的后台任务和状态查询。

## 研究和取证

1. 从用户问题确定公司、证券代码、报告用途和研究截止日。现有信息足够时自主推进，不重复询问已知选项；默认用 `schemaVersion: 2`、`report.profile: "full"`，按内置 V5 质量合同交付 HTML 与 PDF。用户明确要求简短快评时可用 `brief`，并标为非完整研究。
2. 优先用户资料、交易所/公司正式披露；金融连接和检索沿用当前可见工具及已启用“基础金融分析逻辑”“基础数据源”的规则。目录不是业务数据，来源失效就换可用来源；不能假定付费行情或一致预期已开通。
3. 读取原文后保存本地快照，记录来源、发布日期、访问日期、文件 hash、指标、具体报告期、单位及合并/归母口径。证据指向该数据行与期间列，不用整页另一个数字冒充目标事实。PDF 原件和提取文本分别保留 hash；程序不能证明提取忠实性，关键值回到原 PDF 复核。
4. 将事实填入 `packet.json`，格式见 [输入与证据合同](references/packet-contract.md)。缺失项保留缺口，不能填零。研究日、财务基期、估值/行情日和股本生效日分别登记。没有最新数据时写明最近已核验期间，未核验现价不输出市值、P/E、涨跌空间或评级。
5. 阅读 [完整研究与写作标准](references/research-quality.md)，自主补齐业务、经营驱动、资产负债、现金流、预测与估值所需材料。技术验收样例不能作为用户的正式研究成品；资料有限仍先继续检索或核对可用原文，再显式标明缺口，不能用几项财务指标代替完整研究。
6. 必须读取 [市场与季度](references/market-quality.md) 及 [驱动预测与估值](references/valuation-quality.md)。完整研究默认补齐近十二个月真实共同日期价格/基准、最新已披露连续四季度实绩，以及适用的六年三情景驱动 DCF。金融主体先判断方法适用性；无法执行适用方法时显式记录方法缺口。不能将某样例公司的持股比例、交易日数或估值参数硬编码为通用规范。
7. 对重要论点写“支持事实—推论—假设—反证—下次观察”。财务分析解释业务驱动，预测连接现金与价值。缺项先继续取证，仍未补齐则在对应章节和封面显著标不完整；不能用空标题或旧版校验通过宣称完整。

## 计算与写作

依次调用实际可见的专用工具，不把下面参数当成 Bash 命令：

```json
{"command":"doctor"}
{"command":"validate","input":"research/packet.json"}
{"command":"run","input":"research/packet.json","out":"research-run-本次唯一名称"}
```

工具名为 `research_report`，input 是当前会话工作区内的相对路径，out 是工作区根目录下一层尚不存在的目录名。不要传脚本、环境变量、会话ID或绝对路径。固定执行客户端内置引擎，不接受任意程序。工具不可用或失败时保留真实状态；不能搜索凭据、取消环境过滤或启动无认证替代服务。

同比分解、差额、比例和合计用结构化计算请求交给程序。相邻年度同频金额变化使用 `periodDifference`；累计差分还原单季使用 `quarterFromCumulative`，不能放宽普通 `difference` 的期间限制。默认完整模型采用 `driver-fcff-v2`：量价与经营率驱动六年三情景，CAPM/WACC来源、actual365余期、现金滚动、终值g/ROIC再投资、归属/分部股权桥和估值日股本均明确。展示敏感性与现价反解；totalERP已含国家风险时不得重复加CRP。旧版手填固定年期 FCFF 仅作兼容算术检查，不满足完整合同或交易日估值。

`report` 中定量文字通过 `{{事实或计算ID}}` 插入，亿元可用 `{{revenue-current|yi}}`、比例可用 `{{margin|pct}}`；期间可用 `{{period:revenue-current}}`。财务数字不自由手填，引用来源由 `refs` 自动关联。正文、数据表和图表读取同次计算，错误输入不能靠改文稿绕过。数量词等自然语言仍需人工复核，模板检查不代表全文语义正确。

完整研究通过稳定章节 kind 声明业务、行业、业绩、盈利、资产负债、现金流、预测、估值、风险与跟踪的覆盖状态；市场、四季度与模型作为实质专题覆盖；核心论点填 `theses` 中证据、推论、假设、反证和观察条件。部分或缺失资料必须填 `gap` 的缺项、结论影响和补充动作，不能只加空标题。使用引用数值的专题表和同频率图表解释业务驱动；原文观察 `observations` 需逐字定位，不进入确定性计算。按真实问题取舍，不为页数或图表数量凑内容；没有核验行情/同行/预期，相关结论就写缺口。

## 图表的研究用途

写作前阅读 [研究图表标准](references/chart-quality.md)。先按问题选择图：多期实绩回溯用折线，规模与同比用清楚标注左右轴的组合图，少量同频对照可保留柱图，精确加总的变化用瀑布算术桥。通常尽力核验连续多年历史；点数不足、口径重述或资料断点不能靠补零、平滑或连接不可比数据掩盖。业绩回溯指披露实绩，不称预测命中率或投资策略回测。市场日序列和四季度由结构化 `market/quarterly` 数据生成；不把两点月末图当一年走势或未披露季度当实绩。资料不足以建立预测与价值桥时，继续补证并标模型缺口，不编造 DCF 折现图。

## 正式研报编排

写作前阅读 [正式研报封面与内页规范](references/publication-format.md)。使用投研摘要封面：观点大标题、正式报告副标题、公司代码/行业/日期、投资要点、市场/财务基本数据与一年趋势图、历史盈利摘要及预测估值状态；正文提供目录/图表索引、编号专题、三表摘要与证据附录。填 `report.publication` 的真实公司简称、受控报告类别与行业，`report.title` 写本次观点。摘要可加短 `label`，所有数值仍走 token，不写样例公司的数字、评级或作者。资料不足时保留要素和缺口说明，继续核对可用资料。

## 交付

`research_report` 的 `run` 默认同时生成同一正式报告名的 `.html` 与 `.pdf`，名称含公司、证券代码、财务期别、报告类别与研究日期；不再交付通用 `report.html/report.pdf`。机器文件仍为 `evidence.json`、`calculations.json`、`validation.json`、`report-quality.json`、`run.json`。从工具 `artifacts` 的实际绝对路径或 `run.json.artifacts` 映射读取文件名，不能猜测、改名或手填旧文件名。PDF 由客户端内置引擎从同一 HTML 导出，无需另装打印软件。报告固定使用易方达蓝青配色，样式规则见 [报告与配色](references/report-style.md)；无需让用户再选主题。打开实际 HTML 与 PDF，检查中文、分页、表格、图表、来源及真实目录页码，修正后重新生成。只有 `run.json.delivery.completed` 同时包含 html/pdf、产物存在且摘要通过才可声称双格式文件交付；只有 `researchRequirements.standard` 为 `ework-equity-v5` 且 `complete: true` 才可称研究完整。`rendered-with-gaps` 可以保留双格式中间稿，但必须说明研究缺口并继续补证。PDF 失败时命令非零退出、保留 HTML 和失败记录，应修复并重试新目录。客户端任务不能使用 Bash `run` 代替该专用工具。Bash 会按设计过滤敏感环境变量，它的 `doctor` 不能据此判断客户端 PDF 服务不可用；不要以 `--format html` 跳过默认 PDF。用户明确只要网页的特殊要求可用 CLI 单格式检查，并清楚说明实际交付。

向用户同时给正式名称的 HTML 与 PDF 入口，再简述主要判断、数据截止和关键缺口。交付回复保持简短，避免重复长篇定量分析；如确需复述数字，原样读取同次报告的显示结果，不能重新心算、截断或另行舍入。所有报告及辅助 JSON 入口均用工具回执中的完整绝对路径构造 Markdown 文件链接，避免裸文件名被解析成工作区根目录的错误位置。所有产物保存在会话文件区，原始输入与输出 hash 关联到本次运行。证据核验表示本地快照/字段一致，模型通过表示受控公式/勾稽可复算；均不声称外部来源真实或证券研究员专业签发。当前版本不提供原版 LEDGER 五角色盲评、完整三表预测联动或全链路 Excel 重算保证；内置驱动 DCF 的可复算状态不替代来源、经济判断或证券专业签发。
