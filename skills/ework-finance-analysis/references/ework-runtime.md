# EWork 取数与展示规则

## 可用工具与来源

先看当前会话可见的工具和已启用技能，不假定任何第三方服务可用。用户指定通联时，优先当前可见的内置通联 `ework__*` 工具：先搜索 API 或读取目录，再读取接口定义并真实取数；研报、公告和会议纪要用对应检索工具。工具名称使用实际目录返回值，不手拼哈希后缀。MCP 已停用时不调用，也不自动重新开启。

未指定来源时，金融研究优先当前可见通联 MCP；简单报价或其未覆盖的数据可用 `public_data_query`（先 catalog 后 query）、`financial_query`，再用当前可见网页搜索与正文读取工具补充一手资料。“基础数据源”已启用时可加载它选择可用接口；停用时不强制加载其规则。用户提供完整资料或要求离线时直接分析，不联网。来源失败后按实际错误修正参数或使用下一条可用来源，不循环失败接口；工具不可见就明确当前无法取数，不能虚构成功调用或数值。

API 发现结果不是业务数据。调用前读取参数类型、币种、单位、日期、分页和排序，返回后核对目标日期、真实字段路径及空值。财务三表对齐会计周期；净值不能用交易价格代替，ETF不能用其基准指数代替。每个数据块附真实来源与数据时点，获取时刻不能冒充报价时刻。

## 研究与组件协同

方法论用本技能按场景读取最小充分参考集合，取数用当前可用来源，组件生成用“工作台组件生成”技能（已启用时）。金融分析逻辑不能覆盖用户指定的组件种类和宿主 JSON 协议。

股票、ETF、指数等相关主体的行情优先内置个股行情、自选股和市场指数组件；不能把已有专业行情卡改成手写 SVG。其他金融图表使用宿主 `market` / `chart` 专业模板，动态更新数据，文字保持可读，容器缩放时图表重排，不能整体拉伸文字。只有用户明确需要独立 HTML 报告时才使用报告参考，其外部资源应受宿主支持范围约束。

每半小时刷新等需求必须保存并核验宿主刷新绑定，使用成功请求的参数和真实映射路径；静态快照不是持续刷新。提醒或监控仅使用实际可用的日历/定时任务能力，不承诺后台运行或系统推送已生效。

## 可执行分析脚本

完整保留源技能的16个脚本。先读对应参考和脚本输入约定，使用当前环境可用的 Python 和依赖；不在加载技能时自动安装依赖或执行脚本。优先将已核实数据保存为 CSV/JSON 后按脚本的本地文件输入运行，不假定 WorkBuddy 的 westock CLI 已安装。缺少 numpy/pandas/scipy/openpyxl 等依赖时明确限制，使用可用计算工具完成相应计算。脚本计算结果仍须核对缺失值、单位、时间窗口、样本量和假设，不能当作数据源或保证收益。
