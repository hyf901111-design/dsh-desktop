# 1.0.9：封面、目录与常规正文选择

## 封面副标题

复用本版本内置标准封面。中文主副标题、双语第二段、英文副标题和 AI 技术封面副标题均不加粗；主标题、字号、位置、段落数、图片和页脚不变。必须在所有副标题 run、段落默认及段尾属性显式设置 `b="0"`，不能只删除 run 的 b 属性导致继承粗体。`check_efund_cover.py` 以已更新资产为精确参考，粗体回归会失败。用户明确指定自己的模板时仍按该模板参考。

## 目录线条

首行上方不画横线，包括表格顶边和独立线条。首行 `lnT/noFill` 显式覆盖继承样式。每行下分隔保留源稿细灰线样式（V6 目录为 0.5pt 灰色虚线），包括最后一行；删除多余目录项时同时删除对应多余分隔。行间双侧边线不得叠成两条。行距继续执行 toc-spacing-108.md。

原生目录使用 `tocRows` 的 tableId/rowIndex/columnIndex 和 numberCell；独立文本框每行额外写 separatorShapeId。只豁免映射到目录行的原生表格单元格的普通表格无边框检查，页面上的其他表格仍检查。`toc-top-rule-forbidden` 和 `toc-row-separator-mismatch` 必须清零。渲染时还须确认线宽、颜色、首行顶边和逐行分隔。

## 左侧标题正文、右侧图表的选择顺序

这是常规证据正文的默认结构。先逐页判断以下三项是否同时满足：

1. 一条核心结论可用 2–3 条短解释说明。
2. 存在一个能独立承载证据或关系的主视觉：趋势图、对比图、表格、关系图、产品截图或有信息的照片；不必强求数值图表。
3. 右侧 58%–65% 宽度足够保持标签清晰，左侧 35%–42% 宽度足够容纳 15pt 解释标题与 12pt 正文（150% 行距）。

三项满足就默认使用 `left-text-right-visual`。趋势与驱动分析、方案说明加架构示意、产品能力加截图、调研发现加证据表都优先进入这一类；不要因为主题是技术或思想就直接排除。每页围绕实际主张重新布局右图，不照搬上一页几何。

以下结构有具体需要时优先替代：多类别图表或大型矩阵确需全宽；真实长流程需保持顺序阅读；多个同等重要对象确需并列对照；人物时间线或作品关系需沿时间/关系组织。纯装饰图不构成适用依据。不能为提高占比伪造数据、硬塞图表、缩小字体或拆坏逻辑。

每张 content 页必须填写：

```json
"layoutChoice": {
  "eligible": true,
  "selected": "left-text-right-visual",
  "reason": "单一增长结论由季度趋势图支撑，左侧两条解释能够说明驱动因素"
}
```

不适用时 eligible=false，并在 reason 写明不满足的条件。适用但选其他结构时仍写 eligible=true，selected 写实际结构，另写 alternativeReason（如“十二个类别的标签需全宽以保持字号”）。缺少记录或例外理由是硬错误；不能只写“更美观”“换个风格”。固定封面、目录、法务、结束页不纳入。

规划与导出后统计：适用正文页数 E、其中左文右图页数 S、采用率 S/E。建议 S/E 不低于 60%；低于时复核每个替代理由并在 qa-review.txt 说明，合理例外可以通过，不作为数量硬门禁。E=0 写“无适用页”，不能强行补图。整稿同时保持同一结构最多连续两页、超过 8 页至少三种结构；依据故事线变换结构，不为比例打乱叙事。这使常规适用页有明确默认值，同时保留内容主导。
