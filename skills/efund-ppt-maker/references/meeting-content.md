# 办公汇报内容方案

每页选择能说明该页关系的结构。以下数据为格式示例，制作时替换为用户真实内容。单个文本元素的多段说明可用换行分隔。若内容超出版心应拆页。

```json
{
  "title": "服务试点进展",
  "date": "2026年11月",
  "pages": [
    {"kind":"table","title":"试点覆盖与验收目标","rows":[["指标","试点一","试点二"],["服务点","4","8"],["验收率","80%","90%"]],"widths":[2,1,1],"focus":2,"numeric":[1,2],"note":"口径：已完成验收的服务点。"},
    {"kind":"list","title":"下一阶段需要解决的问题","items":[["流程衔接","统一交接表，覆盖两班交接。"],["响应时间","明确值班负责人和升级条件。"]]},
    {"kind":"timeline","title":"三个交付节点","items":[["第一周","确认试点范围。"],["第二周","记录首批反馈。"],["第三周","完成验收。"]]},
    {"kind":"summary","title":"试点决策与依据","items":[["决策建议","扩大至第二批服务点。"],["准备工作","先核验交接清单。"],["验收依据","负责人逐项确认覆盖范围。"]]}
  ]
}
```

`summary` 首项是有证据支持的主结论，后面各项列依据或执行要求。`table` 的重点列和数值列从零计数。先对应原始数据再选强调列。客户定制、流程图、趋势图、地图、素材型演示等不适合硬套上述四种结构；使用完整制作规范和所需原生图表。
