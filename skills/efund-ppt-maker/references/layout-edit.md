# 在原稿上排版

先运行 `layout_edit.py inspect SOURCE`。对象 ID 只在同一页有效，页号从 1 开始。画布宽度归一为 960，高度与原稿成比例。对象位置为左、上、宽、高；空段也占一个段落序号。超过 16 页时，首次只返回各对象的文字节选和行数。需要完整段落或单元格时用 `--slides 2 3` 指定实际页号。制作计划时引用输入文件当前的指纹。

以下示例展示操作格式。尺寸、页号及 ID 仅供说明，须用原稿对象清单和实际图像决定。只列出确实要改的对象。

```json
{
  "sourceSha256": "从 inspect 读取",
  "edits": [
    {"slide": 2, "id": 8, "box": [38, 120, 884, 150],
     "columns": [142, 300, 442], "rows": [30, 40, 40, 40], "header": true},
    {"slide": 3, "id": 5, "blocks": [
      {"count": 1, "box": [38, 117, 250, 50]},
      {"count": 2, "box": [320, 117, 600, 90]},
      {"count": 1, "box": [38, 245, 250, 50]},
      {"count": 2, "box": [320, 245, 600, 90]}
    ]},
    {"slide": 4, "id": 2, "box": [38, 22, 660, 46]}
  ]
}
```

将计划写在临时工作目录，然后执行：

```sh
python3 -B "$SKILL_DIR/scripts/layout_edit.py" apply "$SOURCE" "$PLAN" "$NEW_PPTX"
python3 -B "$SKILL_DIR/scripts/check_efund_package.py" "$NEW_PPTX"
```

- 表格的列宽、行高分别加总至框的宽、高。可选的 `header: true` 应用青色表头和浅色行，`false` 只应用行底色；要保留原有颜色、强调和对齐时省略此字段。合并单元格关系和文字不变。
- 文本框可只调位置大小。普通文本框和纯文字占位符还可按连续完整段落分框，保留原 run、字号、链接和段落样式。各块的 count 合计须等于该框段落数。给同行标题和说明留出各自的宽度，优先按长说明所需的行数分配行高。
- 分组、带动画的对象、装饰性容器、日期与说明同处一个段落等需要针对性设计的情况，可直接在副本上使用本地 PPTX 编辑库。原生图表、附件、批注和母版保持可用。工具对不支持的重排会报错，源文件和已有输出不会被覆盖。
- 在获准使用本机 PowerPoint 的 macOS 环境执行 `osascript "$SKILL_DIR/scripts/review_layout.applescript" "$NEW_PPTX"`。传入成品的绝对路径。脚本将 PDF 写入 PowerPoint 自己的独立临时目录，返回 PDF 路径和实际访问页码。脚本访问每一页，完成时回到封面。以输出的实际页码和导出的 PDF 为证据，再检查最终文字布局、配图和页脚。访问失败时保留具体错误，使用可用的渲染器完成其余检查，将未验证部分如实告知用户。
