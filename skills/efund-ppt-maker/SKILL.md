# 易方达 PPT 制作助手 · 1.2.0

用户本轮指定的文件、目标、范围和交付格式优先。脚本从本技能资源目录运行，使用客户端任务 Python 的 `python3 -B`。把草稿、预览和方案保存在独立临时目录，最终文件默认放到本次工作区，保留原件。

## 优化已有稿

收到“优化版式”“基于新版再优化”时，直接运行以下命令获得首稿；局部修改可在末尾指定 `--slides 3 5`。不要先编写自己的逐页脚本或逐张读取原稿。

```sh
python3 -B "$SKILL_DIR/scripts/meeting_deck.py" optimize "$SOURCE" "$CANDIDATE"
```

工具只重排能识别的数据表、并列要点、摘要和时间线，保留母版及嵌入文件。输出列出每页结果。检查未识别的正文页或用户明确点名的问题页；必要时用 `scripts/layout_edit.py inspect`、[局部编辑](references/layout-edit.md) 或个别页面专用编辑。不要把“已生成候选稿”当作全部页都合格。用户指定的新模板、图表、动效和叙事重构按实际内容单独设计。

## 从文字新建

普通办公汇报先将来源组织成 JSON 方案，每页给出结论标题和内容关系。调用 `python3 -B "$SKILL_DIR/scripts/meeting_deck.py" create "$SPEC" "$CANDIDATE"`。参见[内容方案](references/meeting-content.md)。保留来源中的数字、单位、时点和限定语。封面复用品牌源页，重点列、主结论和时间节点保持可编辑。需要专用图表、架构、照片、其他模板或完整外发审计时，按 [完整制作规范](AUTHORING.md) 及相应图表规范实施，视觉设计同样须体现每页的业务重点。

## 验收与交付

1. 检查读者是否能一眼定位关键年度、逐项对应问题和事实、看出主结论与依据、沿日期读事件、辨认附件。单纯移动框、统一字号、拉开段距不足以通过这些页面的检查。
2. 用最终候选文件运行 `scripts/check_efund_package.py`，再运行 `python3 -B "$SKILL_DIR/scripts/review_meeting.py" "$CANDIDATE"`，只读它返回的拼图。渲染器、页数和 PDF 路径是实际执行结果。发现具体不合格的页，再针对该页放大、修改、复核。检查完成后将已复核的同一文件复制到最终路径。
3. 本轮需要的产物均完成时，先简短说明一个可复核的结果及最终文件链接，再调用 `presentation_files`，参数 `{"paths":["工作区内的最终文件.pptx"],"complete":true}`。成功登记即结束本轮。用户指定工作区外的位置时遵照指定位置交付，直接以精确文件链接结束。多产物任务先完成其他交付，只在最后一次登记时结束。仅有 PPT 请求时不另写 Word、报告、源码或与任务无关的文件。
